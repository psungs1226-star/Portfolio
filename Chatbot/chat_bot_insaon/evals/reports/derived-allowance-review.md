# PAY-01 휴직 파생 정근수당 검증

## 결론

공개 합성 사례 `PAY-01`을 실제 로컬 Qwen3·BGE-M3와 미승인 공식 candidate에 연결했다.
첫 질문에서는 결론을 만들지 않고 결정 조건 6개를 재질문했고, 후속 조건을 입력한 뒤
결정적 코드가 실제 근무기간 6개월과 제6조제1항 정근수당액 대비 100%를 계산했다.

로컬 Qwen은 계산값을 바꾸지 않고 근거 설명을 생성했다. 수당규정 제6조제1항제2호·
제2항, 보수규정 제14조제3호의2, 수당규정 제19조제10항 등 공식 인용 4건을 연결했고
합성 인용은 0건이었다. candidate가 사람 승인 전이므로 최종 제품 상태는
`ANSWERABLE`이 아니라 `REVIEW_REQUIRED`다.

## 실제 확인값

| 단계 | 확인 결과 |
|---|---|
| 최초 질문 | `REVIEW_REQUIRED`, 누락 조건 6개, 모델 호출 0 |
| 후속 조건 | 실제 근무기간 6개월, 지급률 100% |
| 검색 | 기준일 2026-07-01, 전체 심층 vector + temporal filter |
| 인용 | 필수 교차 근거 4/4, 공식 인용 4, 합성 인용 0 |
| 로컬 생성 | Qwen3 4B 사용, 모델 권고 `ANSWERABLE` |
| 최종 상태 | 미승인 candidate gate로 `REVIEW_REQUIRED` |
| 외부 추론 | 없음, API key 필요 없음 |

단일 실행에서 cache가 있는 시작은 1.411초, 후속 답변은 32.126초였고 그중 로컬 생성은
31.255초였다. 이 값은 개발 장비의 한 번 측정한 smoke이며 평균이나 P95로 해석하지 않는다.

## 3회 품질 개선

1. 첫 실기동에서 모델이 15일 잔여일수 환산을 휴직기간 규칙처럼 요약한 문제를 찾았다.
2. 해당 표현을 결정적 출력 검증에서 거부해 잘못된 설명이 노출되지 않는 안전 전환을 확인했다.
3. 사례에 필요한 정확한 조문 구간만 생성 모델에 전달해 6개월·100%와 네 교차 근거를
   유지하면서 잘못된 15일 설명을 제거했다.

이 개선은 모델의 자유 설명 범위를 줄인 것이다. 날짜·개월·비율은 계속 코드가 계산하고,
모델은 확인된 조건과 caller-owned citation ID 안에서만 설명한다.

## 남은 평가

- 공식 candidate 본문·단서·부칙의 독립 사람 승인
- 승인 index를 사용한 독립 법령 locked set
- 동일 조건 3회 이상 반복 latency와 실패율
- 실제 인사담당자의 과업 사용성

원시 측정값은 `artifacts/provider/derived-allowance-smoke.json`에 있다.
