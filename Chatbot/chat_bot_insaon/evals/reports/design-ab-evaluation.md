# 디자인 A/B 평가 계약

## 현재 상태

- protocol: `design-ab-v0.1`
- 비교 대조군: 현재 production dashboard
- 후보군: A Evidence Ledger, B Case Workbench, C Regulation Map
- 후보 선택: B Case Workbench · 포트폴리오 소유자 선택
- 참여자: 0명
- 사람 A/B 결과: 미측정

세 격리 시안의 HTML 계약과 1440×1100·390×844 렌더는 자동·AI 검토 대상이다.
시각 휴리스틱을 사용자 선호, 과업 완료, 법률 정확도나 업무 효과로 해석하지 않는다.

선택 기록은 `design/ab-exploration/selection.json`에 보존했다. B의 대화·조건·근거·검토
노트 구조를 선택했고, production 통합에서 미색·차콜·포레스트 톤, soft rounded shape와
LINE Seed Sans KR의 조금 더 둥글고 굵은 한글 위계를 적용했다. 기술 통합과 브라우저
광학 검수 기록은 `design/production/REVIEW_PACKET.md`에 둔다.

## 동일 과업

| CASE | 양쪽 arm에서 수행할 과업 | 성공 기준 |
|---|---|---|
| A | 누락된 휴직 유형·기준일을 찾고 재질문한다 | 결론 전에 누락 조건을 식별하고 후속 입력 위치를 찾음 |
| B | 과거 기준일에 유효한 근거와 시행일을 찾는다 | 기준일·시행일을 구분하고 원문 위치를 찾음 |
| C | 지원 범위와 기관 규정 미확인 경계를 설명한다 | 보류 이유와 다음 사람 확인 항목을 설명함 |

CONTROL과 CANDIDATE는 같은 CASE·문구·성공 기준을 쓴다. 시안마다 유리한 다른 성공
사례를 배정하지 않는다.

## 분리해 기록할 항목

사람 세션에서는 task completion, 첫 행동 명확성, 근거 발견 단계, 오류 회복, 선호를
각각 기록한다. 참여자가 0명이므로 현재 시간·선호·완료율은 모두 `미측정`이다.

자동 검증은 세 시안 분리, 6개 viewport render, keyboard focus, 한글 어절 줄바꿈,
공개·개인정보 경계만 확인한다. 이것을 사람 사용성 결과로 합치지 않는다.

## 다음 gate

1. CONTROL/CANDIDATE 순서를 교차해 동일 합성 과업을 수행한다.
2. 참여자 수와 중단 세션을 포함해 공개 가능한 집계만 기록한다.
3. 결과를 시각 선호와 과업 사용성으로만 해석하고 법률 품질과 분리한다.

사람 사용성 세션은 아직 시작하지 않았으므로 완료율·시간·선호는 계속 `미측정`이다.
