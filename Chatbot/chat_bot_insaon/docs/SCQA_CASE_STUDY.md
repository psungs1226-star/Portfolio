# SCQA Case Study — 인사ON

## Situation

지방자치단체 인사과 담당자는 육아·질병·가족돌봄·자기개발 휴직과 관련 복직 문의를 처리하면서 법률, 대통령령, 행정규칙, 공개 실무자료와 기관별 규정을 확인한다. 관련 규정은 개정될 수 있고 실제 적용에는 휴직 유형, 대상자 조건과 질문 기준일이 중요하다.

## Complication

단순 키워드 검색은 실무 표현과 법령 용어의 차이를 놓칠 수 있고, 일반적인 벡터 RAG는 현행·과거 조문, 본문·단서·부칙을 섞을 수 있다. 정보가 부족한 질문에도 LLM이 그럴듯한 결론을 만들 수 있으며, 기관별 규정의 존재나 법적 해석 문제를 모델이 임의로 해결할 위험이 있다.

## Question

최종 인사판단을 자동화하지 않으면서도, 인사과 담당자가 휴직 유형별 필수조건과 기준일에 맞는 근거를 빠짐없이 검토하도록 어떻게 지원할 수 있는가?

## Answer

휴직·복직 도메인으로 범위를 제한하고, 육아·질병휴직은 심층 구현하며 가족돌봄·자기개발휴직은 공통 엔진의 확장성을 검증한다. 다음 통제장치를 결합한다.

1. 휴직 유형을 분류하고 유형별 필수 조건이 없으면 먼저 재질문한다.
2. 법령 데이터를 조·항·호·목과 효력기간 단위로 구조화한다.
3. BM25, 벡터 검색, 메타데이터 필터와 재랭킹을 비교한다.
4. 날짜·기간 계산과 문서 효력 필터만 결정적 로직으로 처리한다.
5. LLM은 확인된 근거를 구조화해 설명하며 근거가 부족하면 보류한다.
6. 골든셋과 사람 검토로 검색·인용·조건·거절 성능을 분리해 평가한다.

## 프로젝트가 증명하려는 역량

| 역량 | 공개 증거 |
|---|---|
| 문제 정의 | PRD의 범위·비목표·중단 기준 |
| 데이터 엔지니어링 | 조문·버전 데이터 모델과 변경 diff |
| 검색 시스템 | Baseline/Hybrid/Reranker 비교 |
| AI 통제 | 재질문, 구조화 출력, 답변 보류 |
| 소프트웨어 설계 | 규칙·검색·생성 책임 분리 |
| 평가 | 고정 평가셋, 오류 분류, 재현 가능한 리포트 |
| 공공·HR 도메인 감수성 | 사람 검토, 개인정보 최소화, 기관 규정 경계 |

## 주장과 근거의 경계

- 구현 전에는 목표 지표를 성과처럼 제시하지 않는다.
- 검색 성능 향상이 실제 업무시간 절감을 의미한다고 주장하지 않는다.
- 실무자 3~5명의 의견은 사용성 신호이지 일반화 가능한 효과 검증이 아니다.
- 공개 규정 검색 결과를 최종 법률해석이나 처분 적법성으로 표현하지 않는다.
- 데모가 처리하지 않는 직군과 기관별 규정은 명시적으로 범위 밖으로 표시한다.

## 완성 후 채용자에게 보여줄 이야기

```text
휴직·복직 규정 검토 챗봇을 기획했다
→ 시점·예외·누락 조건 때문에 단순 RAG가 실패했다
→ 네 휴직 유형을 처리할 공통 조건·법령 구조와 질문 처리 책임을 설계했다
→ 검색과 생성 실패를 분리해 평가했다
→ 어떤 경우에 답하지 않아야 하는지도 수치로 검증했다
```
