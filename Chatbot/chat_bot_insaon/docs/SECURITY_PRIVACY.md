# 개인정보·보안 설계

## 1. 기본 입장

인사ON은 포트폴리오용 프로토타입이며 실제 인사자료를 처리하지 않는다. 공개 법령과 합성 사례만 사용하고, 최종 인사결정을 수행하거나 실제 기관 시스템과 연결하지 않는다.

## 2. 수집하지 않는 정보

- 주민등록번호와 외국인등록번호
- 실제 직원의 성명·사번·연락처
- 건강·병력·장애 정보
- 실제 자녀·가족 정보
- 징계·평정·급여·노조 관련 기록
- 기관 내부 문서와 비공개 인사규칙

## 3. 입력 처리

1. 사용자 화면에서 실제 개인정보 입력 금지를 고지한다.
2. 서버 진입 전에 대표 식별자 패턴을 탐지한다.
3. 민감정보 의심 시 모델 호출을 중단하고 합성값으로 바꾸도록 안내한다.
4. 질문 원문을 기본 로그에 저장하지 않는다.
5. 디버그 로그는 로컬 개발 환경에서만 짧게 보관하고 공개 데이터로 대체한다.

패턴 탐지만으로 개인정보를 완전히 식별할 수 있다고 주장하지 않는다.

ADR-0016의 `core` 재질문은 실제 직원의 건강·자녀·돌봄 정보를 입력하라는 허가가 아니다.
공개 데모와 평가는 합성값만 사용한다. `normal_case_assumption`은 제품이 만든 조건부 값으로
질문 확인값이나 세션 사실에 저장하지 않고, 사용자가 합성 예외를 명시한 경우에만 해당
가정을 제거한다. 기관 규정 미수집 상태는 `없음`으로 저장하지 않고 `미확인`으로 유지한다.

## 4. 로컬 모델 사용

- MVP의 생성·임베딩·재랭킹은 `127.0.0.1` loopback runtime에서 실행한다.
- API key나 외부 추론 endpoint를 사용하지 않는다.
- HTTP proxy 환경을 무시하고 redirect를 금지해 의도하지 않은 외부 전송을 차단한다.
- Ollama server는 `OLLAMA_NO_CLOUD=1`과 loopback bind로 실행한다.
- 원클릭 런처가 Ollama를 시작할 때도 같은 환경을 강제하고, API key를 읽거나 생성하지 않는다.
- 로컬 실행도 실제 개인정보 처리 허가를 뜻하지 않으며 입력 gate와 무원문 로그 원칙을 유지한다.
- 개발·평가에는 공개 규정과 합성 사례 ID만 사용한다.

## 5. 프롬프트 인젝션

법령과 실무자료도 신뢰할 수 없는 입력으로 취급한다.

- 검색 문서 안의 명령문을 시스템 지시로 실행하지 않는다.
- 문서 텍스트와 시스템 지시를 명확히 분리한다.
- 허용된 출력 스키마만 반환한다.
- 검색 문서가 외부 URL 호출이나 비밀 공개를 요구해도 무시한다.
- 인용되지 않은 핵심 결론은 검증 단계에서 차단한다.

## 6. 권한과 운영

MVP는 공개 데이터만 제공한다. 향후 기관별 문서를 다룰 경우 사용자·기관·문서 단위 접근통제를 검색 전 단계에 적용해야 하며, 권한 없는 문서는 임베딩 검색 후보에도 노출하지 않아야 한다.

current 자료 13종과 과거 효력 재현용 버전 4종으로 넓힌 17개 source도 공식 공개 규정뿐이다. 징계·평정·급여 관련 `규정`을 검색하는 범위가 넓어지는 것이며, 실제 직원의 징계·평정·급여 데이터 입력이나 처리는 계속 금지한다. 정근수당 PAY-01도 공개 합성 기간·상태값만 사용하고 개인정보 gate와 무원문 로그 경계를 그대로 통과한다.

## 7. 위협 시나리오

| 위협 | 통제 | 남는 위험 |
|---|---|---|
| 실제 주민번호 입력 | 패턴 탐지와 요청 차단 | 비정형 개인정보는 놓칠 수 있음 |
| 악성 문서 명령 | 데이터·지시 분리, 출력 스키마 | 새로운 공격 패턴 |
| 존재하지 않는 조문 인용 | source ID 검증 | 존재하지만 문맥이 다른 인용 |
| 과거 조문 혼용 | 효력기간 필터 | 복잡한 부칙 해석 |
| 내부 규정 누락 | 검토 필요 상태 | 사용자가 경고를 무시할 수 있음 |
| 평가 데이터 노출 | 비공개 정답 분리 | 개발자의 간접 기억 |

## 8. 고지문

> 이 서비스는 공개 규정을 기반으로 인사업무 검토를 보조하는 프로토타입입니다. 실제 개인정보를 입력하지 마십시오. 결과는 최종 인사처분 또는 법률해석을 대신하지 않으며, 담당자가 질문 기준일의 원문과 기관별 규정을 확인해야 합니다.

## 9. 후속 local model·pilot 보안 gate

phase 06~09에서도 실제 직원 정보 처리 범위는 확대하지 않는다.

- 실제 모델은 `local` profile을 명시적으로 선택하고 loopback exact allowlist와 artifact digest를 확인한다.
- 개인정보 의심 입력, 조건 누락과 범위 밖 질문은 로컬 generation 호출 전에 종료한다.
- 모델 request·response 원문과 질문 원문을 로그·평가 artifact·오류 응답에 저장하지 않는다.
- 실제 법령 raw·processed·index와 locked 정답은 비제출 경계에 두고 공개 artifact에는 hash·version·집계만 둔다.
- pilot은 공개 법령·합성 과제만 사용하며 실제 기관 시스템이나 직원 자료와 연결하지 않는다.
- hosting, 공식 source 접근권한, 승인자 또는 참여자가 없으면 관련 후속 Harness step은 `blocked`로 유지한다.

phase 06의 local runtime은 `127.0.0.1:11434` 이외의 모델 endpoint를 거부하고 API key를
읽지 않는다. 모델 파일은 Git에 포함하지 않으며 공개 manifest에는 content digest와
실행 metadata만 둔다.

production 설정은 `legal_validation_candidate`, 승인 index manifest 경로, 정확한
HTTPS CORS origin과 trusted host, local runtime을 모두 요구한다. API는 16 KiB 요청
상한, 분당 요청 제한, CSP·frame·MIME·referrer·cache·HSTS header와 별도 readiness를
적용한다. 구체적인 hosting·보존·incident·rollback 계약은 ADR-0008과
`docs/PILOT_RUNBOOK.md`를 따른다.

채팅 대시보드는 현재 session ID만 DOM에 보관하고 localStorage·sessionStorage·cookie에
질문 원문이나 답변을 저장하지 않는다. 품질 탭은 고정된 공개 artifact 경로의 집계만
읽으며 `private/` 파일을 탐색하거나 브라우저로 전달하지 않는다. UI의 CSS·JavaScript는
same-origin 정적 파일로 분리하고 인라인 실행 없이 CSP `default-src 'self'` 경계에서
동작한다.
