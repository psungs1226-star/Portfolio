# ADR-0013: 휴직 파생 정근수당을 제한된 심층 검토로 분리한다

> 공개 MVP에서는 ADR-0017에 따라 비활성화했다. 이 문서는 연구 레인의 회귀 결정 기록으로만 유지한다.

- 상태: Accepted
- 날짜: 2026-08-04
- 관련 요구사항: FR-02~FR-07, FR-10~FR-13
- 후속 결정: ADR-0016이 이 ADR의 정상 시나리오를 공통 정책의 최초 등록 profile로 편입한다

## 배경

`육아휴직 복직자의 상반기 정근수당은 100%인가 50%인가`는 보수·수당 단어가 포함돼
기존에는 넓은 `evidence_only` 검색으로만 처리됐다. 이 경로는 관련 조문 후보는 보여도
휴직기간의 승급기간 산입 여부와 실제 근무개월을 계산하지 않아 질문의 핵심을 답하지
못했다. 반대로 보수 전반을 심층 범위로 올리면 호봉·연봉·성과상여금과 기관별 지급기록까지
무리하게 자동 판단하게 된다.

기존 local RAG에는 세 가지 구현 결함도 있었다.

- Vector는 lexical 상위 48개만 임베딩해 독립 의미 검색이 아니었다.
- Temporal filter 전에 후보를 잘라 낮은 순위의 유효 과거 버전을 잃을 수 있었다.
- 휴직 심층 답변 문맥에 고정 조문 목록을 먼저 넣어 실제 검색 결과의 역할이 약했다.

## 결정

1. 일반 보수·수당은 계속 `evidence_only`로 둔다.
2. 육아휴직·복직과 정근수당 지급률이 함께 등장한 질문만
   `regular_service_allowance_review` 심층 레인으로 분류한다.
3. 산정 반기·복직일·이번 휴직기간은 비율 계산의 핵심값으로 두고, 없으면 재질문한다.
   단, 한국어·ISO·점 표기 단일 휴직기간이 포함 종료일로 제시되고 완료된 복직 표현이
   있으며 별도 복직일이 없으면 내부 반개구간 종료값을 복직일로 파생한다. provenance는
   `derived_leave_period_end`이며 통상 가정이 아니다. 복수 기간·복직 표현 없음·잘못된
   날짜에는 파생하지 않고, 명시 복직일이 기간 종료와 다르면 충돌로 재질문한다.
   세 핵심값과 질문 기준일이 있으면 `regular-service-allowance-normal-v1`을 최초 등록
   profile로 사용하고, 사용자가 명시하지 않은 허용 필드에만 정상 시나리오를 적용한다.
   사용자에게는 ① 같은 자녀 합산 기본 한도 1년 이내, ② 지급일 재직·봉급 지급,
   ③ 징계·직위해제 등 지급 제외기간 없음과 연봉제 별도 미지급 대상 아님의 3묶음으로
   표시하고 조건부 비율을 먼저 제공한다. 실제 적용한 내부 필드만 `assumed_conditions`에
   넣고, 가정은 확인값과 분리해 세션 사실로 저장하지 않으며 결과는 `REVIEW_REQUIRED`로
   제한한다. 사용자가 실제 예외를 입력하면 해당 확인값이 정상 가정보다 우선한다. 그 필드는
   가정에서 제외하고 해당 조건으로 다시 계산하거나 지급대상 경계로 전환하되, 나머지
   미지정 필드에는 정상 가정을 계속 적용한다.
   이 profile은 ADR-0016의 공통 우선순위와 기본 거부 원칙을 따르며 다른 휴직 유형으로
   자동 확장하지 않는다.
4. 상반기는 해당 연도 7월 1일 지급 기준일과 수당규정 제6조제1항제2호, 하반기는 다음
   연도 1월 1일 지급 기준일과 제6조제1항제1호로 변환한다. 선택한 반기의 경계 조문과
   제6조제2항·제19조제10항, 보수규정 제14조제3호의2를 질문 확장 검색으로 회수하고,
   네 종류 근거가 모두 없으면 답변을 보류한다. 반대 반기 경계 조문으로 대체하지 않는다.
5. 근무개월과 지급률은 `RuleService`가 계산한다. Qwen은 계산 결과를 바꿀 수 없고 근거와
   확인 경계를 구조화해 설명한다. Qwen 설명이 육아휴직 산입을 반대로 쓰거나 질문에 있는
   휴직을 없다고 하면 해당 설명은 노출하지 않고 검증된 교차 조문 기반 문장으로 대체한다.
   모델의 권고 상태와 실행 여부는 별도로 남긴다.
6. H2/H3는 lane 전체 후보를 받은 뒤 source·topic·효력·대상을 필터하고 `top-k`를 자른다.
   Local vector는 심층 lane 전체를 BGE-M3로 임베딩하며 lexical shortlist를 쓰지 않는다.
7. 전체 vector는 candidate 경계 밖 비제출 cache에 저장한다. embedding artifact·version,
   source hash와 provision ID가 모두 일치할 때만 재사용한다.
8. 휴직 일반 문맥의 고정 조문 anchor 주입을 제거하고 검색·관계 확장 결과만 사용한다.

## 결과

- 합성 사실조건 PAY-01에서 산입 육아휴직 3개월과 복직 후 근무 3개월을 합쳐 6개월·
  100%를 계산한다.
- 같은 자녀 기본 산입 12개월을 이미 쓴 반대 사례는 확대 요건이 없을 때 3개월·50%다.
- 징계, 지급일 봉급 미지급, 연봉제 별도 미지급 대상은 비율보다 지급대상 경계를 먼저
  반환한다.
- 최초 full-vector 생성 시간과 디스크 사용량이 늘어난다. 같은 corpus의 다음 기동은
  versioned cache를 재사용한다.
- 공식 candidate는 자동 구조 감사만 통과했고 사람 승인을 받지 않았다. 계산·인용·모델
  검증이 통과해도 최종 제품 상태는 `REVIEW_REQUIRED`다.

## 제외한 대안

- 보수·수당 전체를 deep-review로 확대: 조건 스키마와 독립 평가가 없어 채택하지 않았다.
- 복직 후 실제 근무 3개월만 보고 50% 고정: 보수규정 제14조제3호의2에 따라 산입되는
  육아휴직을 누락해 결론을 뒤집을 수 있어 제외했다.
- lexical 상위 후보에만 BGE-M3 적용: 빠르지만 vector recall을 lexical recall에 종속시켜
  H1/B1 비교와 실제 의미 검색 계약을 깨므로 제외했다.
- Qwen이 직접 개월과 비율 계산: 날짜·기간 계산을 생성 모델에 맡기지 않는 책임 분리와
  재현성 원칙에 어긋나 제외했다.
