# ADR-0014: 사용자 채팅 흐름과 화면 안 근거 확인을 기본 정보구조로 선택한다

## Context

Case Workbench는 대화·조건·근거·품질 상태를 한 화면에 모았지만 세션 ID, 진행 단계,
품질 탭과 내부 모델 상태가 챗봇 사용자의 주 과업보다 강하게 보였다. 공식 원문 링크는
법령정보센터의 전체 HTML을 바로 열어 사용자가 필요한 조문을 다시 찾아야 했다.

포트폴리오 소유자는 인사담당자가 질문 결과를 바로 이해하도록 짧은 가정, 조문이 설명하는
의미와 유의사항을 사용자 언어로 제공하고, 원문은 화면 안에서 먼저 확인하도록 요청했다.

## Options

1. 기존 3열 Case Workbench와 품질 탭을 유지한다.
2. 대화만 남기고 조건과 근거를 모두 접힌 영역에 숨긴다.
3. 채팅과 근거·유의사항의 2열을 사용하고 화면 안 조문 미리보기를 제공한다.

## Decision

옵션 3을 선택한다.

- 결론, 짧은 가정, 적용 근거, 유의사항을 질문 다음의 읽기 흐름으로 둔다.
- 가정은 `같은 자녀 육아휴직 1년 이내`, `7월 1일 재직기준`,
  `지급제외조건(징계 등) 없음`으로 묶어 표시한다.
- `담당자 확인` 대신 `유의사항`을 사용하고 보고서식 종결어를 사용자 존댓말로 바꾼다.
- `원문 확인`은 화면 안 dialog에 조문 발췌, 출처, 조문 경로와 시행일을 표시한다.
- 공식 법령정보센터 링크는 dialog 안 보조 동작으로 유지한다.
- 품질 탭, 세션 ID, 모델 ID와 내부 상태 코드는 사용자 기본 화면에서 제거한다.
- API의 구조화 필드, 보수적 상태 병합, 인용 검증과 로컬 모델 경계는 바꾸지 않는다.

## Consequences

- 사용자는 외부 페이지로 이동하기 전에 답변과 조문의 연결을 읽을 수 있다.
- 운영 품질 정보는 API와 공개 artifact에 남지만 챗봇 화면에서는 직접 탐색할 수 없다.
- 외부 법령 사이트의 표시 방식이 바뀌어도 기본 근거 읽기는 citation 발췌로 유지된다.
- 화면 단순화의 실제 과업 완료율·선호·법령 이해도는 아직 측정하지 않았다.

## Revisit

- 실제 인사담당자 사용성 세션에서 근거 발견이나 후속 질문이 지연될 때
- 긴 조문이 dialog에서 읽기 어렵거나 원문 맥락이 부족할 때
- 운영 품질 화면을 별도 관리자 경로로 공개할 필요가 생길 때
