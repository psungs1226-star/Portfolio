# ADR-0024 생략형 후속은 앞 턴의 과업을 이어받는다

- 상태: 채택
- 날짜: 2026-08-11
- 관련: ADR-0021(대화 단위 평가), ADR-0010·0017(lane 분리), ADR-0016(통상 가정)

## 배경

ADR-0021에서 평가를 대화 단위로 바꾸자 `conversation.elliptical_followup`이 B0부터 H4까지
**0/4**로 나왔다. 검색 구성과 무관했다.

```
1턴: 2026-01-02 기준으로 육아휴직 공개 근거 조문을 찾아주세요.
     → ANSWERABLE · 인용 6건

2턴: 질병휴직는요?
     → REVIEW_REQUIRED · 인용 0건
        "검토하려면 질병휴직의 공무상·비공무상 구분만 알려주세요."
```

사용자는 같은 일(근거 조문 찾기)을 대상만 바꿔 물었는데 제품은 조건을 처음부터 다시 물었다.

당시 ADR-0021은 이것을 **안전한 방향의 실패**로 보고 고치지 않았다. 틀린 답을 만드는 것이
아니라 더 묻기 때문이다. 게이트를 푸는 방식으로 "고치면" 필수 조건 없이 결론을 만들지
않는다는 규칙을 깨게 되므로, 측정해서 한계로 공개하고 "과업을 이월하되 게이트는 유지하는
분류 규칙"을 별도 결정으로 미뤘다. 이 문서가 그 결정이다.

미뤄둔 판단이 틀렸던 지점도 있다. 이 결함은 안전하게만 실패하지 않았다 — 아래 "고치다
드러난 것"을 보라.

## 원인

`QuestionClassifier.classify`는 매 턴을 독립적으로 읽는다. 과업(intent)은 텍스트에 있는
표지로만 정한다.

```python
intent = "evidence_lookup" if any(t in text for t in ("근거","규정","조문","찾아")) else "eligibility_review"
```

"질병휴직는요?"에는 그 표지가 없다. 그래서 자격 검토로 떨어지고, 자격 검토의 필수 조건에는
`medical_leave_basis`가 있으므로 되묻는다. **대화 어디에도 "앞 턴이 근거 검색이었다"는
사실이 남아 있지 않았다.** 이월되는 것은 조건값(`leave_type`, `reference_date`)뿐이었다.

## 결정

### 1. 과업을 대화 상태로 남긴다

`ConditionExtractor`가 매 턴 `task` 조건을 남긴다. 값은 그 턴의 intent다. 사용자가 주장한
사실이 아니라 요청의 종류이므로,

- `confirmed_conditions`에서 뺀다 — 묻지도 않은 것을 확인했다고 되읽지 않기 위해서다.
- 화면의 조건 목록(`visibleConditionNames`)에도 넣지 않는다.

주제가 바뀌면 `session.merge_conditions`가 다른 조건과 함께 버린다. 이월과 폐기 규칙을 한
곳에 두기 위해 별도 저장소를 만들지 않았다.

### 2. 생략형 어미로 끝나는 턴만 이어받는다

```python
_elliptical_tail = re.compile(r"[은는도]\s*요?\s*\?\s*$")
```

`…은요?` `…는요?` `…도요?` `…은?` `…는?`. 서술어가 없다는 것이 표지다. `되나요?`
`며칠인가요?`는 앞 글자가 은/는/도가 아니라 걸리지 않는다.

**"과업 표지가 없으면 이월"이 아니라 "생략형이면 이월"이다.** 처음에는 전자로 구현했는데
`2026년 4월 1일 질병휴직 조건`처럼 주어를 온전히 다시 말하는 질문까지 이월 대상이 되어,
넓은 lane에서 심층 검토로 넘어가는 턴이 조건 게이트를 건너뛰었다. 기존 테스트가 잡았다.
생략형은 "주어만 갈아끼웠다"는 뜻이고, 그것을 판정하는 것은 어미다.

이 턴이 스스로 과업을 말했으면(`조문`, `되나요`) 어미가 맞아도 이어받지 않는다. 사용자가
한 말이 앞 턴의 맥락보다 우선한다.

### 3. 게이트는 풀지 않는다

이어받는 것은 과업뿐이다. 필수 조건 판정은 그대로 `ConditionPolicy`가 한다. 근거 검색
과업의 필수값은 휴직 유형과 기준일이고, 비어 있으면 이 경로로도 되묻는다.

```
1턴 근거 검색 → 2턴 "질병휴직는요?"   → ANSWERABLE      · 인용 7건
1턴 근거 검색 → 2턴 "질병휴직 되나요?" → REVIEW_REQUIRED · 공무상 구분을 묻는다
1턴 자격 검토 → 2턴 "질병휴직는요?"   → REVIEW_REQUIRED · 공무상 구분을 묻는다
```

세 번째가 핵심이다. 이월은 근거 검색으로 고정된 것이 아니라 **앞 턴이 무엇이었든 그것**을
잇는다. 자격 검토 대화에서 유형만 바꾸면 새 유형의 결정적 사실을 여전히 묻는다.

## 고치다 드러난 것

이 수정을 넣고 유형 전환 96조합(4유형 → 3유형 × 표기 2종 × 어미 4종)을 전수로 훑었다.
잠금 평가셋에 없던 결함 둘이 나왔다. **둘 다 되묻는 실패가 아니라 틀린 답을 내는 실패였다.**

### 줄여 부른 유형

`가족돌봄은요?`에는 `휴직`이 없다. `_leave_terms`가 잡지 못해 유형 미상이 되고, 그러면 앞
턴의 유형을 되살리는 기존 이월 규칙이 걸려 **육아휴직 조문으로 답했다.** 화면에는
`ANSWERABLE`과 인용 5건이 뜬다. 사용자가 조문 번호를 직접 대조하지 않으면 모른다.

줄임말 표(`육아`/`질병`/`가족돌봄`/`자기개발`)를 두되 **생략형 후속에서만 해석한다.**
어디서나 읽으면 "자녀 질병 간호입니다" 같은 가족돌봄 대화의 조건 답변이 질병휴직으로
lane을 바꾼다. 단발 질문에서 `질병` 두 글자로 유형을 단정하지 않는 이유도 같다.

### 한 턴이 유형을 둘 부를 때

`질병이랑 가족돌봄은요?`는 유형 미상이 맞다. 그런데 앞 턴의 `leave_type`이 CONFIRMED로
남아 있어 되살아났고, 역시 묻지 않은 유형으로 답했다. 이것은 이번 수정과 무관하게 원래
있던 결함이다 — 전체 표기(`질병휴직이랑 가족돌봄휴직은요?`)에서도 같았다.

한 턴이 유형을 둘 이상 부르면 앞 턴이 확정한 유형은 더 이상 이 질문의 답이 아니다.
`_merge_conditions`에 무효화 목록을 넣어 그 턴에 한해 확정값을 버리고 되묻게 했다.

이월 규칙이 새 `QuestionClassification`을 만들면서 `reason_code`를 떨어뜨리고 있던 것도
같이 고쳤다. 모호 판정이 지워져 무효화가 발동하지 못했다.

## 결과

| 지표 | 전 | 후 |
|---|---:|---:|
| `conversation.elliptical_followup` | 0/4 · 0.000 | **4/4 · 1.000** |
| `conversation.resolution_rate` | 8/12 · 0.667 | **12/12 · 1.000** |
| `answer.status_accuracy` (H3) | 66/70 · 0.943 | **70/70 · 1.000** |
| `citation.completeness` (H3) | 54/58 · 0.931 | **58/58 · 1.000** |
| 유형 전환 96조합 교차 누수 | 미측정 | **0건** |

**두 지표가 1.000이 됐다는 것은 이 잠금셋이 포화됐다는 뜻이다.** 70건으로는 더 이상 검색
구성을 가르지 못한다. 아직 가르는 것은 Set Recall@5(0.944)와 H2의 치명적 오류 8건뿐이며,
판별력은 케이스를 늘려서 되찾아야 한다. 수치가 좋아진 것을 성과로 적지 않는다.

회귀는 `tests/integration/test_conversation_sweep.py`가 고정한다. 96조합 전수와 어미 4종
이월, 게이트 유지, 모호 되묻기를 함께 검사한다.

## 대안과 기각 사유

- **생략형 후속에서 조건 게이트를 통과시킨다** — 기각. 그러면 `질병휴직는요?`가 공무상·
  비공무상 구분 없이 결론을 받는다. 이 구분은 통상값이 없는 분류값이고(ADR-0016), 어느
  조문을 적용할지 자체가 바뀐다.
- **앞 턴 질문 원문을 저장해 이어 붙인다** — 기각. 대화가 사용자가 친 문장의 저장소가 된다.
  `ReviewConversation`은 구조화 조건만 들고 있으며 이 경계는 개인정보 규칙에 걸려 있다.
- **줄임말을 `_leave_terms`에 그냥 넣는다** — 기각. `질병`이 단발 질문에서도 유형을 단정하게
  되고, `자녀 질병 간호로 가족돌봄휴직`이 두 유형 매칭으로 모호해져 지금 맞는 답이 되묻기로
  퇴화한다.
- **어미 대신 문장 길이로 판정한다** — 기각. 임의값이고, 같은 뜻의 긴 문장과 다른 뜻의 짧은
  문장을 반대로 가른다.

## Revisit

- 어미 4종만 이어받는다. `그럼 질병휴직?`(어미 없음), `질병휴직 쪽은 어떤가요?`(우회 표현)는
  걸리지 않고 되묻기로 떨어진다. 틀린 답은 아니지만 이월도 아니다.
- 수량 생략형(`그럼 2년은요?`, `1년 더 쓰면요?`)은 다루지 않았다. 어미는 맞지만 바뀌는 것이
  주어가 아니라 조건값이라 별개 문제다.
- 잠금셋에 유형을 둘 부르는 케이스가 없다. 위 수정은 전수 훑기와 회귀 테스트로만 지킨다.
