# ADR-0026 넓은 lane의 기준일은 오늘로 가정한다

- 상태: 채택
- 날짜: 2026-08-11
- 관련: ADR-0016(통상 가정 정책), ADR-0010·0017(lane 분리), ADR-0025(범위 판정 어휘)

## 배경

ADR-0025로 `가점` 거절을 고친 뒤, 실제 담당자가 쓰는 FAQ 문장으로 확인했다. corpus 조문
제목으로 만든 질문은 어휘를 그 제목에서 뽑았으므로 순환 검증이라 쓰지 않았다.

날짜를 붙인 32건은 전부 정상이었다. **날짜를 빼자 전부 막혔다.**

```
징계 시효는 몇 년인가요?        → REVIEW_REQUIRED · 인용 0건
                                "적용할 규정을 찾으려면 질문 기준일만 알려주세요."
공무원 정년 몇 세예요?          → 같음
병가 며칠까지 쓸 수 있어요?      → 같음
인사기록카드 보존기간이요        → 같음
시간외근무수당 상한 알려주세요    → 같음
배우자 출산휴가 며칠이에요?      → 같음
```

실제 사용자는 "질문 기준일"이라고 쓰지 않는다. 라우팅도 검색도 멀쩡했는데 화면에는
아무것도 답하지 못하는 제품으로 보였다. **넓은 lane에서는 빠진 것이 기준일 하나뿐이라
그 되묻기가 곧 막다른 길이었다.**

## 결정

넓은 lane(`review_tier == "evidence_only"`)에서 기준일이 없으면 **오늘로 가정한다.**

과거 기준일 질의는 이미 지원 범위가 아니라고 공개해 두었다(README 한계). corpus는 법령마다
현행과 과거 스냅샷 두 개를 갖는 것이지 모든 중간 개정본을 갖지 않는다. 그러면 이 lane에서
통상값이 될 수 있는 값은 오늘뿐이다.

ADR-0016의 규칙을 그대로 따른다.

- 명시값이 이긴다 — `2026-08-04 징계 시효` 는 가정하지 않는다.
- 가정 사실을 답변에 싣는다(`assumed_conditions`, `normal_case_assumptions_applied`).
- `reference-date-today-v1` profile에 속한다. 승인된 profile 없이 가정하지 않는다.
- 상태는 `REVIEW_REQUIRED`를 넘지 못한다.
- 세션의 확정 조건으로 저장하지 않는다.

### 심층 검토에는 걸지 않는다

휴직·복직은 결론을 만드는 lane이고, 자녀 생년월일·공무상 구분 같은 결정적 사실을 어차피
함께 묻는다. 기준일은 그 한 번의 되묻기에 얹히므로 **막다른 길이 아니다.** 결론을 만드는
경로에서 날짜를 조용히 채우는 것은 다른 문제다.

```
넓은 lane   징계 시효는 몇 년인가요?              → 인용 5건 · 가정: 기준일
심층 lane   공무상 질병으로 질병휴직 되나요?        → 기준일만 되묻고, 답하면 인용 7건
```

처음에는 모든 lane에 걸었고 테스트 10건이 깨졌다. 그중 심층 lane의 실패들은 규칙이
바뀌어서가 아니라 **바꾸면 안 되는 것을 바꿔서** 깨진 것이었다. 범위를 좁혔다.

## 고치다 드러난 것 — 생년월일이 기준일로 샜다

FAQ를 짜다가 `자녀가 2025년 3월 2일생인데 육아휴직 얼마나 쓸 수 있나요?` 만 되묻지 않고
바로 답하는 것을 봤다. 확인해 보니 이랬다.

```
child_birth_date = 2025-03-02
reference_date   = 2025-03-02   ← 같은 날짜
```

**질문을 2025년 3월 시점의 법령으로 판단하고 있었다.** 되묻지 않고 `REVIEW_REQUIRED`와
인용이 함께 뜨므로 조문 번호를 직접 대조하지 않으면 알 방법이 없다.

원인은 정규식이 두 벌이라는 것이었다. 필드 추출은 넓은 `_child_birth_patterns`를 쓰고,
기준일 추출의 배제 검사는 `자녀 생년월일:` 형태만 걸러내는 **좁은 접두사 정규식을 따로**
갖고 있었다. 두 벌이 어긋난 만큼 생년월일이 기준일로 샌다. 지난 작업에서 넓은 쪽을
`2025년 3월 2일생`, `2025. 3. 2. 태어났습니다`, `2025-03-02 출생아`까지 확장했는데, 그때
이 구멍도 같이 넓혔다.

배제 검사가 **필드가 실제로 쓰는 패턴의 span을 그대로 보도록** 고쳤다. 한 벌만 유지한다.
휴직 기간·복직일은 원래 이 방식이었고, 생년월일만 예외였다.

## 결과

| | 전 | 후 |
|---|---:|---:|
| 날짜 없는 넓은 lane FAQ 20건 | 0/20 답변 | **20/20** 답변 + 핵심 조문 인용 |
| 날짜 있는 FAQ 32건 | 32/32 | 32/32 |
| 생년월일 표기 4종의 기준일 누수 | **4/4 누수** | **0/4** |
| 도메인 밖·corpus 공백 질문 | 거절 | 거절(유지) |

잠금 회귀셋 지표는 움직이지 않았다. 잠금셋에는 넓은 주제 케이스가 한 건도 없고
(README 한계에 이미 적혀 있다) 다회차 케이스는 기준일을 명시하기 때문이다. **이 결함들은
합성 평가셋이 재지 못하는 자리에 있었다.**

회귀는 `tests/integration/test_hr_faq.py`가 잡는다. 날짜 없는 FAQ 20건 × 2종(핵심 조문
회수 · 가정 공개), 심층 lane 4종의 "한 번 묻고 답한다", 생년월일 누수 4종, 그리고 범위
밖 4종을 함께 검사한다.

## 대안과 기각 사유

- **모든 lane에서 오늘로 가정한다** — 기각. 결론을 만드는 심층 검토에서 날짜를 조용히
  채우면 자녀 생년월일과의 관계로 결론 자체가 바뀐다. 그쪽은 막다른 길도 아니었다.
- **기준일을 아예 필수에서 뺀다** — 기각. 명시했을 때 그 값이 이겨야 하고, 화면에는
  가정했다는 사실이 떠야 한다. 필수에서 빼면 두 성질이 모두 사라진다.
- **가정하되 화면에 알리지 않는다** — 기각. 담당자는 자기가 확인해야 할 시점을 모른 채
  조문을 읽게 된다. 이 제품이 하는 일의 반대다.
- **`오늘`을 질문 텍스트로 주입해 검색한다** — 기각. 기준일 필터는 생성 모델 호출 전에
  결정적 로직으로 수행한다는 규칙에 걸린다.

## Revisit

- `오늘`은 서버 시각이다. 기관 담당자가 다른 시점을 보려면 명시해야 하고, 그 사실은
  가정 표시로만 전달된다. 화면에서 가정된 날짜 자체를 보여주는지는 따로 확인하지 않았다.
- 심층 lane의 기준일 되묻기는 그대로 남는다. 한 번의 되묻기지만 되묻기이며, 그 UX가
  충분한지는 측정하지 않았다.
- FAQ 20건은 이 합성 corpus가 담고 있는 주제로만 짰다. 실제 담당자 질문 분포가 아니다.
