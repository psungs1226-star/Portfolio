# 제출 답변 기획 초안

## Phase 0 확정 문제 문장

글로벌 뷰티/홈에스테틱 제품의 인플루언서 시딩 의사결정을 온톨로지, 인과 가설, 반복 실험 루프로 바꾸는 Codex 플러그인.

## 문항 1 초안: 무엇을, 누가, 어떤 상황에서 쓰나요?

메디테라피의 글로벌 뷰티/홈에스테틱 마케터가 인플루언서 후보, 콘텐츠 맥락, 제품 적합성, 예상 매출 기여 가설을 구조화해 “매출로 이어질 가능성을 검증할 수 있는 인플루언서 시딩”을 설계하도록 돕는 Codex 플러그인이다.

사용자는 북미 TikTok, Instagram Reels, Amazon review/Live 등에서 제품별 인플루언서 후보를 고르는 마케터다. 후보가 많고, 피부 고민/콘텐츠 형식/팔로워 니즈/제품 리스크가 서로 얽혀 있어 “누구에게 어떤 제품을 보내야 실제 구매 가능성이 생기는지”를 판단하기 어려운 상황에서 쓴다.

## 문항 2 초안: 왜 이 문제를 선택했나요?

메디테라피 공개 자료로 방어 가능한 문제는 단순 인플루언서 리스트업이 아니라, 시딩 의사결정이 매출과 연결될 가능성을 설명하고 반복적으로 검증하는 시스템을 만드는 것이다. AX 인재전쟁 메디테라피 영상은 온톨로지, 인과관계 추정, 반복 가능한 루프를 강조하고, 글로벌 TikTok 마케팅 채용공고는 북미 인플루언서 발굴/협상/계약/시딩, 제품별 메시지 및 숏폼 기획, 광고 데이터 분석을 업무로 제시한다.

따라서 이 문제는 공개 근거로 확인 가능한 니즈와 연결되어 있고, 메디테라피의 글로벌 성장 방향과도 맞으며, Codex 플러그인이 “수집 -> 분류 -> 추천 -> 검증 -> 반복”을 설계하기에 적합하다. 다만 실제 매출 인과는 내부 클릭, 쿠폰, 주문, 재구매 데이터가 연결된 뒤에만 검증 가능한 것으로 제한한다.

## 문항 3 초안: 플러그인은 어떻게 작동하나요?

플러그인은 먼저 인플루언서 후보의 공개 데이터를 표준 파라미터로 수집한다. MVP 기준은 북미 TikTok 중심 후보 30명, 숏리스트 12명, 시딩 추천 6명, 대조군 3명이며 후보당 최근 콘텐츠 10개를 관찰한다.

그다음 후보를 피부 고민, 콘텐츠 형식, 팔로워 구매 의도, 채널/국가 적합도, 리스크 신호로 분류한다. 제품은 히알루론산 퍼스트 세럼, PDRN 세럼, 판테놀 크림, 레티날 세럼, AHA/BHA 클렌저, 비타민 버블세럼, 트라넥삼산 크림, 텐션 업 마스크, 링클핏 아이패치 9개를 MVP 대상으로 둔다.

추천은 단순 점수가 아니라 인과 가설로 출력한다. 예를 들어 “민감/트러블 루틴을 자주 다루는 후보에게 PDRN 세럼을 시딩하면 저장률과 민감피부 관련 구매 질문이 증가할 가능성이 있다”처럼 제품, 후보, 콘텐츠 각도, KPI, 리스크를 함께 제시한다. 데이터가 부족하거나 리스크가 크면 추천을 보류하거나 누락 데이터 질문을 출력한다.

동작은 phase harness로 관리한다. Phase 0에서 문제와 공개 근거를 고정하고, Phase 1에서 제품 온톨로지를 만든다. Phase 2와 3에서는 인플루언서 후보 수집과 파라미터 정규화를 가장 엄격하게 수행한다. Phase 4에서 제품-인플루언서 매칭을 만들고, Phase 5에서 시딩 브리프를 작성한다. Phase 6에서 성과를 수집하고, Phase 7에서 `5.4 mini reviewer`가 코드와 기획 의도를 독립 검수한다. Phase 8은 반복 학습, Phase 9는 제출 패키징이다.

## 문항 4 초안: AI를 어떻게 썼나요?

AI는 공개 자료 조사, 문제 구조화, 제품군 파라미터 분할, 인플루언서 후보 분류 기준 설계, 추천 출력 계약 설계에 사용했다. 특히 온톨로지, 인과 가설, 반복 실험 루프를 플러그인 동작 구조로 바꾸는 데 활용했다.

직접 판단한 부분은 MVP 범위, 제품 추천에서 성별을 1차 기준으로 쓰지 않는 정책, 내부 매출 데이터 없이 매출 효과를 단정하지 않는 검증 원칙, 리스크가 높은 효능/의료 표현을 감점 또는 차단하는 기준이다.

받아들이지 않을 AI 제안은 단순 팔로워 수 기반 랭킹, 성별 기반 제품 추천, 내부 데이터 없이 ROAS를 확정하는 표현, 의료적 효능을 단정하는 시딩 문구다.

## 문항 5 초안: 어떻게 검증했나요?

검증은 대회 MVP 검증과 실무 확장 검증으로 나눈다.

대회 MVP에서는 입력 JSON 스키마 검증, 추천 점수 휴리스틱 검증, 대표 인플루언서 케이스 검증, 리스크 차단 검증, `5.4 mini reviewer`의 독립 리뷰를 수행한다. 리뷰어는 코드와 기획 의도가 맞는지, 제품 파라미터와 추천 사유가 충돌하지 않는지, 매출 효과를 과도하게 단정하지 않았는지, 리스크와 누락 데이터 질문을 포함했는지 확인한다.

검증은 phase별 게이트로도 수행한다. 후보 수집 단계에서는 30명 중 최소 24명이 필수 필드를 충족해야 하고, 각 후보는 최근 콘텐츠 10개 또는 부족 사유를 가져야 한다. 파라미터 정규화 단계에서는 피부 고민, 콘텐츠 형식, 댓글 의도, 리스크가 근거 URL과 confidence를 가져야 한다. 매칭 단계에서는 hard exclusion을 먼저 적용하고, 추천 사유가 본인 피부 적합도, 팔로워/시장 적합도, 콘텐츠 적합도, 채널/국가 적합도, 리스크로 분해되어야 한다. 시딩 수행 단계에서는 콘텐츠 브리프, 금지 표현, KPI, 대조군이 모두 남아야 한다.

정상 예시는 트러블/장벽 콘텐츠를 반복하는 후보에게 PDRN 세럼 또는 판테놀 크림을 추천하고, 저장률과 민감피부 질문 수를 KPI로 설정하는 케이스다. 예외 예시는 임신/수유를 공개했거나 민감피부 자극을 호소하는 후보에게 레티날 제품을 추천하지 않고 차단 또는 대체 제품을 제시하는 케이스다.

아직 부족한 점은 실제 매출, 클릭, 쿠폰, 장바구니 데이터가 없으면 매출 인과를 확정할 수 없다는 점이다. 그래서 대회 제출에서는 공개 데이터로 0-2단계 KPI를 시연하고, 내부 데이터 연결 시 3-4단계인 클릭/쿠폰/주문/재구매로 확장되는 구조를 제시한다.

# 최종 MVP 반영 보강: 제출 답변에 추가할 내용

2026-07-09 최종 패키징 기준으로 아래 내용은 제출 답변에 반영하는 것이 좋다. 기존 초안의 방향은 유지하되, 최종 구현물이 실제로 무엇을 산출했는지 더 분명히 보여준다.

## 문항 1 보강: 플러그인 한 문장

메디테라피 글로벌 뷰티 마케터가 신제품을 입력하면 공개 인플루언서 DB를 바탕으로 제품-크리에이터 적합도, 콘텐츠 맥락, 리스크, KPI를 평가하고, 시딩 후보와 선정 사유 보고서를 생성하는 Codex 플러그인이다.

## 문항 3 보강: 실제 산출물 중심 설명

최종 MVP는 신제품 입력값을 받아 `Phase 6A`에서 기존 인플루언서 DB 30명을 다시 랭킹하고, `Phase 6B`에서 추가 리서치가 필요한지 판단한다. 최신 테스트에서는 메디테라피 신제품 `포쎄라 리얼 비피다 핑크 블러 크림`을 입력으로 사용했고, 추천 후보 6명을 생성했다.

플러그인은 단순 JSON 결과만 내지 않는다. 마케터가 바로 판단할 수 있도록 `logs/new_product_ranking_report.html`을 필수 생성한다. 이 HTML 보고서에는 최종 순위표, 후보별 점수 분해, 한국어 선정 사유, 피부 고민 매칭, 콘텐츠 매칭, 리스크 판단, 검증할 가설, 실행 방향, 관찰 KPI가 포함된다. 내부 태그는 보조 근거로만 남기고, 보고서 본문은 “왜 이 후보가 이 제품을 자연스럽게 말할 수 있는지”를 한국어 해석으로 설명한다.

정보가 부족하거나 리스크가 큰 후보는 고신뢰 추천에 넣지 않는다. `hard exclusion`, `needs_more_data`, `review_required` 후보는 분리해서 보여주고, 실제 게시/클릭/쿠폰/주문 데이터가 없으면 매출 효과를 단정하지 않는다.

## 문항 5 보강: 최종 검증 결과

최종 검증은 압축 파일을 실제로 풀어 `src`를 독립 플러그인 루트로 실행하는 방식까지 포함했다. 압축 해제 후 아래 명령을 실행했고, 모두 통과했다.

```bash
python3 tools/run_phase6a_new_product_ranking.py
python3 tools/run_phase6b_research_gap.py
python3 tools/run_prepackage_tests.py
```

패키징 전 테스트는 10개 전부 `pass`였다. 검사 항목은 Python 스크립트 컴파일, JSON/JSONL 문법, Phase validation 최신본, 핵심 데이터 계약, 보고서 산출물 계약, 리스크 가드레일, 비밀정보 노출, 매출/ROAS/주문 단정 표현, 제출 패키징 준비도다.

테스트 과정에서 실제로 고친 점도 있다.

- 처음에는 순위 결과가 점수와 내부 태그 중심이라 보고자가 판단하기 어려웠다. 이를 HTML 보고서로 바꾸고, 후보별 선정 사유를 한국어 해석 중심으로 재구성했다.
- `makeup_adherence_issue`, `skincare_routine` 같은 내부 태그가 보고서 본문에 과하게 노출되던 문제를 수정해, 내부 태그는 “근거 태그” 보조 섹션에만 남겼다.
- 최종 ZIP 점검 중 `src` 루트에서 도구를 직접 실행하면 `src/logs`가 없어 실패하는 문제를 발견했다. `submission/src/logs`를 포함하도록 패키징을 고쳐 독립 실행 테스트까지 통과시켰다.

최신 산출물 기준으로 제출 ZIP에는 `src/.codex-plugin/plugin.json`, `src/skills/meditherapy-influencer-seeding/SKILL.md`, README, logs, data, tools가 들어 있고, `answers.md`는 제출 패키지에서 제외한다. `logs/new_product_ranking_report.html`과 `src/logs/new_product_ranking_report.html`은 포함되어 있다.

검증은 플러그인의 판단 흐름을 기준으로 했습니다. 신제품 입력 -> 제품 온톨로지 변환 -> 후보 30명 랭킹 -> 추천 6명/보류 후보 분리 -> HTML 선정 사유 보고서 생성까지 같은 입력에서 같은 결과가 재현되는지 확인했습니다. 정상 예시는 포쎄라 리얼 비피다 핑크 블러 크림입니다. 플러그인은 이 제품을 트러블, 붉은기, 피부결, 메이크업 밀착 고민과 연결하고, @milkydew, @cherryblossom216 등 6명을 추천했습니다. 각 추천에는 피부 고민 매칭, 콘텐츠 맥락, 리스크 판단, 인과 가설, 관찰 KPI가 함께 생성되는지 확인했습니다.

예외 상황도 따로 검증했습니다. 의료·시술·과장 표현 리스크가 큰 후보는 점수가 높아도 no_seed_hard_exclusion으로 제외했고, 공개 데이터가 부족한 후보는 needs_more_data로 분리했습니다. 또한 공개 조회수나 댓글 반응만으로 매출, ROAS, 주문 증가를 주장하지 않는지 검사했습니다.

테스트하며 고친 점은 세 가지입니다. 처음에는 결과가 내부 태그와 점수 중심이라 마케터가 판단하기 어려웠습니다. 그래서 한국어 선정 사유와 HTML 보고서를 필수 출력으로 바꾸었습니다. 또 needs_more_data 후보가 상단 추천처럼 보일 수 있어 표시 우선순위를 ready -> review_required -> needs_more_data로 고정했습니다. 아직 부족한 점은 실제 게시 후 클릭, 쿠폰, 주문 데이터가 없어 매출 인과는 검증 전 가설로만 남긴다는 점입니다.
