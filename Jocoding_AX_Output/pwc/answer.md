## 문항 3. 플러그인은 어떻게 작동하나요?

- 입력값
- 작동 절차
- 사용하는 지식 또는 기준
- 정보가 부족할 때의 행동
- 결과물 형태
- 현재 기본 플러그인은 `src/skills/company-problem-evidence/SKILL.md`의 지침으로 한 기업, 공개 근거, 사실/가정/부족한 정보 분리를 기준으로 작동하도록 둠.
- 결과물 예시: `samil_pwc_ax_analysis.html`처럼 회사 개요, AX/AI 포트폴리오, SWOT, 문제정의 후보, 출처 링크를 한 페이지 시각화로 정리.
- 결과물 예시 추가: `samil_pwc_tax_deepdive.html`처럼 최신 전체 매출, 과거 세무자문 세부 매출, 공개되지 않은 세무 하위항목을 구분해서 보고.
- 작동 후보: 법령 변경 입력 -> 관련 키워드/조문/요건 추출 -> 기존 해석례·집행기준 후보 검색 -> 영향 가능성, 근거, 확인 필요사항을 리스트로 출력.
- Agent 탑재 시 행동: 유불리 판단이 필요한 사안은 단정 답변 대신 회계법인 전문가 문의 필요성을 안내.
- 내부문서 활용 시 행동: 영향 가능성이 큰 업종/거래/고객군을 추려 선제 영업·홍보 소재로 사용.
- 구현 범위 후보: 최신판례는 기존 Tax Agent 업데이트 자산을 활용한다고 보고, 이번 스킬은 해석례와 집행기준 변화 감지에 집중.
- 설계 산출물: `tax_agent_skill_architecture.md`와 `tax_agent_skill_architecture.html`에 부가가치세 MVP 기준 스킬별 아키텍처, 데이터, 파싱, 분류, 검증 루프를 정리.
- 실행계획 산출물: `tax_agent_pipeline_worktree.md`와 `tax_agent_pipeline_worktree.html`에 00~06을 Phase로 두고, 그 아래 세부 작업을 Step 단위로 세분화.
- 최종 산출물 형태(스킬 목표): `tax_agent_review_list.html` — 파이프라인 최종 출력을 HTML로 렌더. '법 개정은 시행됐으나 현행 집행기준(2024-09 판본)에 미반영이라 해석 변경 여지 있는' 집행기준 검토 후보를 3구역(확정 누락 1 / 구조적 미반영 6 / 확인 필요 8)으로 제시하고, 자구정비·과대매칭은 제외구역에 분리. 안전표현('검토 후보', 확정 아님)과 한계(26-41-1만 본문 확정)를 명시. 진행현황 대시보드는 `tax_agent_pipeline_status.html`.
- 재검토 판단: MVP는 더 줄여서 부가가치세 1개 쟁점, 집행기준 관련 기준/문단, 세법해석정비 전후 해석례 보조 데이터, 전문가 검토 리스트 산출에 집중하는 편이 안전.

- 해석 변경 정도 측정 방향: 법령 변경이 기존 해석의 대상·요건·효과·예외·시점 중 무엇을 흔드는지 기준으로 영향 강도를 나눔.
- 검증 방향: 실제 변경된 해석례는 정답셋으로 쓰고, 해석례가 없는 영역은 논리주제별 전문가 검토 라벨과 반례 문서로 검증.

- 첫 쟁점 선정 기준 변경: 간이과세자/세금계산서/매입세액공제 중 사전 선호로 고르지 않고, 세법해석정비 데이터에서 정비 사례 수가 가장 많은 쟁점을 우선 선택.

- 제외 재확정: 내부지침, 기재부 해석, 기본통칙은 API 확보와 범위 통제가 어려워 1차 MVP에서 제외.

- 직접 판단한 일
- 막혔던 지점
