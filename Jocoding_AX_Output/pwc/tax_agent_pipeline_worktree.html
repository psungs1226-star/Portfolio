Step 0. 정답셋 기반 첫 쟁점 선정

첫 쟁점은 사전 선호로 고르지 않고, 세법해석정비 데이터에서 정답셋을 가장 많이 만들 수 있는 부가가치세 쟁점으로 선택합니다.

1

세법해석정비 데이터 수집

정비 전/후 문서번호, 정비 요지, 관련 법령, 정비 사유, 공개일을 수집합니다.

2

부가가치세 필터링

세목과 관련 법령을 함께 확인해 부가가치세 사례만 남깁니다.

3

쟁점 태그 분류

주 쟁점 1개와 보조 쟁점 N개로 나누고 태그 과다 부여를 막습니다.

4

정비 사례 수 집계

total_count보다 usable_count, law_linked_count, non_trivial_count를 우선합니다.

5

정답셋 품질 점수

전후 비교 가능성, 관련 조문 명확성, 단순 문구정비 제외 여부를 점수화합니다.

6

첫 MVP 쟁점 확정

issue_score가 가장 높고 반례 문서를 만들 수 있는 쟁점으로 Step 1~6 범위를 고정합니다.

수집 범위 원칙

  • 부가가치세법은 개정 조문과 직접 관련 조문만 수집합니다.
  • 시행령은 구체 요건 확인용으로 함께 수집합니다.
  • 시행규칙은 서식·절차 변경이 있을 때만 포함합니다.
  • 조세특례제한법은 직접 연결되는 특례가 있을 때만 포함합니다.

매칭 기준 원칙

  • 단순 키워드보다 대상, 요건, 효과, 시점을 우선합니다.
  • 조문 직접 일치는 강한 신호로 봅니다.
  • 키워드만 일치하는 문서는 낮은 신뢰도로 둡니다.
  • 근거가 없으면 영향 후보에서 제외하거나 보류합니다.

Step 1. 법령 변경 정규화

부가가치세 개정 자료를 대상, 요건, 행위, 효과, 예외, 시점으로 구조화합니다.

1

수집 범위 확정

부가가치세법, 직접 연결 시행령, 필요 시 시행규칙과 조세특례제한법 일부만 선택합니다.

2

원천 데이터 수집

법령 본문, 신구조문대비표, 개정 이유, 시행일, 부칙을 API 필드로 저장합니다.

3

조문 구조 파싱

조, 항, 호, 목, 단서, 괄호 문구, 적용례, 경과조치를 계층 구조로 분리합니다.

4

변경 전후 비교

삭제·추가 문구, 숫자 변경, 의무 표현 변경, 대상 범위 변경을 추출합니다.

5

법적 논리 단위 추출

대상, 요건, 행위, 효과, 예외, 시점으로 정규화합니다.

6

변경 유형 분류

대상 변경, 요건 변경, 금액 기준 변경, 절차 변경, 의무 변경 등으로 분류합니다.

7

정규화 결과 검수

필수 필드와 시행일, 적용례, 변경 전후 문구, 검토 flag 누락 여부를 확인합니다.

Step 2. 기준문서 사전 정규화

집행기준을 법령 변경과 비교 가능한 형태로 미리 정리합니다. 해석례는 정답셋과 보조 판단용으로만 제한 수집합니다.

1

문서군 범위 확정

Step 0에서 확정된 첫 MVP 쟁점 1개와 반례 생성을 위한 유사 쟁점으로 제한합니다.

2

집행기준 수집

Step 0 확정 쟁점과 관련 조문 기준으로 집행기준 범위를 고정합니다.

3

집행기준 구조 파싱

기준번호, 원칙, 예외, 예시, 주의사항을 분리합니다.

4

해석례 보조 수집

세법해석정비 전후 사례를 우선 수집하고, 부족할 때만 같은 쟁점의 해석례를 제한적으로 추가합니다.

5

문서 구조 파싱

제목, 본문, 관련 조문, 대상, 요건, 효과, 예외, 시점으로 분리합니다.

6

태그 부여

세목, 문서유형, 납세자, 거래, 쟁점, 조문 태그를 붙입니다.

7

검색 인덱스 생성

조문번호, 문서번호, 제목, 태그, 벡터 인덱스를 구성합니다.

8

품질 검수

필수 메타데이터, 원문 출처, 비밀정보 제거, 태그 누락을 확인합니다.

Step 3. 법령 변경과 기준문서 매칭

정규화된 법령 변경과 기준문서를 조문, 키워드, 법적 논리 단위, 시간 조건으로 연결합니다.

1

조문 직접 매칭

변경 조문과 문서의 관련 조문이 일치하는지 확인합니다. 시행령 변경은 위임 법률 조문으로 확장합니다.

2

키워드 매칭

핵심 용어와 동의어를 비교하되 범용 키워드 단독 일치는 낮게 봅니다.

3

대상·요건·효과 매칭

간이과세자, 공급대가, 발급 의무처럼 법적 논리 단위가 겹치는지 봅니다.

4

의미 검색 매칭

조문번호가 없는 문서를 보완하기 위해 벡터 검색을 사용합니다.

5

시간 조건 필터링

문서 생산일과 시행일을 비교해 기존 해석 영향 후보인지 구분합니다.

6

후보 점수화

조문 일치, 대상, 요건, 효과, 키워드, 의미 검색, 시간 조건으로 점수화합니다.

7

중복 후보 병합

같은 집행기준 번호와 개정일, 같은 해석례 문서번호를 기준으로 병합하고 모든 근거를 보존합니다.

Step 4. 영향 가능성 분류

후보가 왜 영향을 받을 수 있는지 설명 가능한 유형과 신뢰도로 나눕니다.

영향 유형

직접 영향, 요건 영향, 대상 영향, 절차 영향, 금액 기준 영향, 예외 영향, 해석 충돌 가능성

신뢰도

조문 직접 일치, 논리 단위 일치, 원문 근거, 시행일 관계, LLM 추정 의존도를 합산합니다.

제거 기준

세목 불일치, 납세자 불일치, 거래 유형 불일치, 단순 단어 유사성만 있는 후보는 제외합니다.

근거 있음 추정 확인 필요 제외

Step 5. 결과물 생성

영향 후보를 내부 검토자가 바로 볼 수 있는 변경 예상 목록으로 변환합니다. Agent 가드레일과 영업자료는 선택 활용안입니다.

1

내부 검토 리스트

우선순위, 영향 유형, 신뢰도, 관련 문서, 확인 필요사항을 정리합니다.

2

문서 변경 예상 목록

변경 예상 집행기준, 보조 검토 해석례, 보류 문서를 분리합니다.

3

신규 검토 논리주제

기존 해석례는 없지만 새 대상, 요건, 예외, 시점 문제가 생긴 쟁점을 분리합니다.

4

선택 활용안 분리

Agent 가드레일, 고객군 요약, 영업자료 초안은 기본 산출물과 분리합니다.

5

최종 리포트 검수

근거 누락, 단정 표현, 문서/논리주제 혼합, 선택 활용안 혼입을 제거합니다.

Step 6. 검증 루프

과거 부가가치세 개정 사례로 영향 후보 탐지 품질을 검증하고 개선합니다.

1

개정 사례 선정

영세사업자 관련성이 있고 개정 전후 문구와 관련 문서가 있는 사례를 고릅니다.

2

정답셋 구축

영향 문서, 비영향 유사 문서, 애매한 문서, 판단 사유를 저장합니다.

3

자동 실행

Step 1~5를 실행하고 영향 후보 리스트를 저장합니다.

4

정답셋 비교

Recall, Precision, Evidence Rate, Safety Rate, Review Usefulness를 봅니다.

5

실패 원인 분류

조문 파싱 실패, 동의어 부족, 요건 추출 실패, 키워드 오탐 등을 분류합니다.

6

룰 개선

태그 사전, 조문 연결표, 점수 가중치, 제거 기준, 프롬프트를 수정합니다.

7

재실행 기록

후보 개수, 정답 포함 여부, 오탐 개수, 개선 전후 차이를 기록합니다.

페이즈 진행 전 결정사항

  • 세법해석정비 데이터에서 가장 정답셋이 많은 첫 데모 쟁점 결정
  • API에서 받을 수 있는 법령 필드와 해석례 필드 확인
  • 집행기준 데이터를 어떤 형식으로 받을지 결정
  • 세법해석정비 전후 해석례 API에서 받을 수 있는 필드 확인
  • 정답셋으로 쓸 과거 부가가치세 개정 사례 선정
  • 최종 산출물은 내부 검토용 리포트로 고정하고, Tax Agent 가드레일은 선택 활용안으로 둘지 결정

재검토 결과

큰 구조는 유지하되, MVP에서는 범위를 더 줄이고 매칭 로직을 하드 필터 중심으로 보강합니다.

축소할 항목

  • 내부 실무지침은 1차 MVP에서 제외
  • 기재부 해석·기본통칙은 1차 MVP에서 제외
  • 벡터 검색은 조문/논리 매칭 실패 시 보조로만 사용
  • 영업·홍보 소재는 선택 출력으로 축소
  • 정답셋은 최소 1개 사례부터 시작

확정 MVP 범위

  • 부가가치세 1개 세목
  • 세법해석정비 데이터에서 issue_score가 가장 높은 부가가치세 쟁점 1개
  • 부가가치세법 조문과 직접 연결 시행령
  • 집행기준 관련 기준/문단 우선, 해석례는 정답셋·보조 판단용
  • 전문가 검토 리스트를 기본 산출물로 고정

보강된 매칭 순서

Hard Filter
  -> Direct Link
  -> Logic Match
  -> Keyword Match
  -> Semantic Match
  -> Evidence Check
  -> Score

세목, 문서유형, 납세자 유형, 거래 유형, 시간 조건이 맞지 않으면 후보에서 제외하거나 보류합니다. 키워드는 보조 신호이며, 대상과 요건이 동시에 맞지 않으면 높은 신뢰도를 줄 수 없습니다.

구간주요 실패검수 로직

Step 2집행기준 범위 확대, 해석례 과다 수집, 태그 과다 부여Step 0 확정 쟁점으로 집행기준을 제한하고 해석례는 정답셋·보조 판단용으로만 사용
