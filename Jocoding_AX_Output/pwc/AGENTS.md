# Project Instructions

이 저장소는 AX 해커톤 예선 제출물을 준비하는 작업 공간이다.

## 금지사항

- 코드의 생성, 추가, 변경, 검증과 관련된 장문 로그를 터미널창이나 대화에 띄우지 말 것.
- `logs/` 아래 파일은 열람, 출력, 요약, 발췌, 편집, 삭제하지 말 것.
- 자동 생성 로그, JSONL, HTML 원문, PDF 원문, 빌드 로그, 테스트 전체 로그를 통째로 출력하지 말 것.
- `cat logs/...`, `sed logs/...`, `rg ... logs/`, `tail logs/...`처럼 로그 내용을 읽는 명령을 사용하지 말 것.
- 외부 페이지나 PDF를 `curl`로 확인할 때는 원문을 터미널에 바로 출력하지 말고, 필요한 경우 임시 파일에 저장한 뒤 `rg`로 필요한 키워드 주변만 확인할 것.
- 명령 출력은 문제 해결에 필요한 최소 줄만 확인한다. 긴 파일은 `sed -n`으로 좁은 범위만 읽고, 검색은 `rg -n`에 구체 키워드를 넣어 제한한다.
- 검증 명령은 성공/실패와 핵심 오류만 남긴다. 전체 로그가 필요한 상황이면 파일에 저장하고, 최종 답변에는 핵심만 짧게 요약한다.
- 대화 답변에는 터미널 출력 전문을 붙이지 않는다. 사용자가 명시적으로 요청해도 필요한 부분만 짧게 발췌한다.

- 패치 적용 내용, diff hunk, +/- 라인, 변경 전후 코드 블록을 대화에 길게 노출하지 말 것.
- 파일 변경은 조용히 수행하고, 결과 보고는 변경 파일명과 핵심 요약만 남길 것.
- 실패한 명령도 긴 오류 로그를 그대로 띄우지 말고 출력 토큰을 작게 제한한 뒤 원인만 요약할 것.

## 핵심 원칙

- 사용자가 최종 답변을 직접 정제한다.
- 에이전트는 대화에서 새로 나온 사실, 판단, 검증 내용을 `answer.md`의 해당 문항 아래에 짧게 추가만 한다.
- 과제 해석, 제출 구조, 일반 설명처럼 답변 작성에 직접 필요하지 않은 긴 배경 설명은 `answer.md`에 넣지 않는다.

## answer.md 기록 규칙

- `answer.md`는 문항별 메모장이다.
- 새 내용은 관련 문항 아래에 짧은 bullet로 append 한다.
- 기존 bullet을 임의로 고치거나 삭제하지 않는다.
- 사용자의 표현과 판단을 우선 기록하고, 에이전트가 문장을 예쁘게 정제하지 않는다.
- 어느 문항에 넣을지 애매하면 가장 관련 있는 문항 아래에 `추가 메모:`로 남긴다.
- 사용자가 명시적으로 "수정해", "정리해", "삭제해", "덮어써"라고 요청한 경우에만 해당 범위 안에서 수정한다.

## 모델 역할 (메인 · 검수자)

- 메인 모델(작업 수행): **GPT-5.5**.
- 검수자 모델(리뷰·적대검증): **GPT-5.4**.
- 이 역할로 진행하는 것이 기본값이다. 실제 사용 모델이 위와 달라지면 `README.md`에 그 변경(모델명·시점·역할)을 반드시 별도로 기록한다.

## 로그 보존

- `logs/` 안의 기존 로그 파일은 절대 수정, 정리, 발췌, 덮어쓰기, 삭제하지 않는다.
- 자동 훅이 생성하는 `logs/codex/*.jsonl`, `logs/claude-code/*.jsonl` 등은 그대로 둔다.
- 해커톤 본문상 AI 대화 로그는 편집·발췌 없이 제출해야 한다.
- 비밀정보(API 키, 토큰, 비밀번호)는 대화나 파일에 남기지 않는다.
