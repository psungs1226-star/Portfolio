# Tax Agent 보강 스킬 아키텍처 설계

## 0. 결론 요약

- 이번 대회 범위는 **부가가치세 1개 세목**으로 제한한다.
- 1차 대상 사용자는 **회계법인 임직원**이다.
- 핵심 목적은 세법 개정이 기존 **집행기준**에 미칠 수 있는 영향을 선제적으로 찾는 것이다.
- 1차 산출물은 **내부용 변경 예상 검토리스트**다.
- Tax Agent 응답 가드레일과 영업·홍보 소재는 내부 검토리스트 이후의 선택 활용안이다.
- 구현은 거대한 세법 AI가 아니라 **작은 정답셋으로 검증 가능한 영향 탐지 파이프라인**으로 설계한다.
- 최신 판례는 기존 Tax Agent 자산이 있다고 보고, MVP에서는 **집행기준 중심**으로 진행한다. 해석례는 정답셋과 보조 판단 사례로만 사용한다.

## 1. MVP 범위

### 선택 세목

부가가치세

### 선택 이유

- 영세사업자, 개인사업자, 간이과세자에게 실제 문의 수요가 많다.
- 과세/면세, 세금계산서, 매입세액공제, 간이과세, 신고/납부 등 쟁점이 명확하다.
- 법인세보다 대상 고객군이 넓고, 소득세보다 MVP 범위를 자르기 쉽다.
- 회계법인의 Tax Agent 확장성과 내부 영업자료 활용 가능성이 모두 있다.

### 제외 범위

- 모든 세목 전체 대응
- 모든 판례 수집
- 모든 예규/해석례 완전 수집
- 자동 세무 자문 결론 생성
- 납세자에게 유리/불리한 최종 판단 단정

## 2. 전체 구조

```text
법령 변경 입력
  -> 변경 조문 파싱
  -> 핵심 요건/키워드 추출
  -> 관련 집행기준 검색
  -> 영향 가능성 분류
  -> 내부용 변경 예상 검토리스트 생성
  -> 선택적으로 Tax Agent 가드레일 또는 내부 활용안으로 확장
```

## 3. 스킬 구성안

### Skill 1. 법령 변경 입력 정규화 스킬

#### 역할

개정 법령 자료를 받아서 Tax Agent가 처리할 수 있는 구조화 데이터로 바꾼다.

#### 입력

- 개정 법령 전문
- 신구조문대비표
- 개정 이유
- 시행일
- 적용례/경과조치
- 사용자가 직접 붙여넣은 변경 조문

#### 출력

```json
{
  "tax_type": "VAT",
  "law_name": "부가가치세법",
  "article": "제XX조",
  "effective_date": "YYYY-MM-DD",
  "change_type": "신설|개정|삭제|문구수정|금액기준변경|요건변경",
  "before_text": "...",
  "after_text": "...",
  "changed_terms": ["간이과세자", "세금계산서", "매입세액"],
  "applicability": ["개인사업자", "영세사업자"],
  "transition_rule": "...",
  "raw_source_id": "..."
}
```

#### 파싱 방식

- API로 받은 법령 데이터를 우선 사용한다.
- PDF/HWP 원문은 가능하면 API 또는 변환된 텍스트를 사용한다.
- 신구조문대비표는 표 구조를 보존해 `before_text`, `after_text`로 분리한다.
- 조문번호, 항, 호, 목은 정규식과 룰 기반 파서로 추출한다.
- 시행일, 적용례, 경과조치는 별도 필드로 분리한다.

#### 주요 분류 기준

- 세목: 부가가치세
- 변경 유형: 신설, 삭제, 요건 변경, 기준금액 변경, 신고절차 변경
- 영향 대상: 간이과세자, 일반과세자, 면세사업자, 전자상거래, 플랫폼, 임대업 등
- 실무 영역: 세금계산서, 매입세액공제, 면세/과세 구분, 신고납부, 가산세

## 4. Skill 2. 세무 기준문서 수집·인덱싱 스킬

#### 역할

법령 변경과 대조할 기준문서 저장소를 만든다.

#### 수집할 데이터

| 데이터 | MVP 필요도 | 용도 |
|---|---:|---|
| 부가가치세법 | 필수 | 변경 조문 기준 |
| 부가가치세법 시행령 | 필수 | 세부 요건 확인 |
| 부가가치세법 시행규칙 | 권장 | 서식·절차 확인 |
| 부가가치세 집행기준 | 필수 | 1차 영향 후보 탐지 |
| 세법해석정비 전후 해석례 | 필수 | 정답셋과 보조 검증 |
| 기타 국세청 해석례 | 선택 | 판단 사례가 부족할 때만 보조 |
| 기획재정부 해석 | 제외 | API 확보와 범위 통제가 어려워 1차 제외 |
| 기본통칙 | 제외 | 집행기준 중심 MVP 이후 보강 |
| 내부 실무지침 | 제외 | 이번 MVP의 메인이 아니며 API 확보 어려움 |
| 판례 | MVP 제외 | 검증용 일부만 사용 |

#### 문서 단위

문서를 통째로 검색하지 않고 아래 단위로 쪼갠다.

- 법령: 조, 항, 호, 목
- 시행령/시행규칙: 조, 항, 호
- 집행기준: 기준 번호 또는 문단
- 세법해석정비 해석례: 정비 전/후 문서번호, 요지, 관련 법령

#### 저장 스키마

```json
{
  "doc_id": "vat_interpretation_2024_001",
  "doc_type": "집행기준|세법해석정비해석례|법령|시행령",
  "tax_type": "VAT",
  "title": "...",
  "published_date": "YYYY-MM-DD",
  "effective_date": "YYYY-MM-DD",
  "source_url": "...",
  "article_refs": ["부가가치세법 제XX조"],
  "issue_tags": ["매입세액공제", "간이과세자"],
  "taxpayer_tags": ["영세사업자", "개인사업자"],
  "transaction_tags": ["전자상거래", "부동산임대"],
  "text": "...",
  "summary": "...",
  "embedding_text": "..."
}
```

#### 인덱싱 방식

- 키워드 검색 인덱스: 조문번호, 문서번호, 제목, 쟁점 태그 검색
- 벡터 검색 인덱스: 질의/회신/집행기준 본문 의미 검색
- 메타데이터 필터: 세목, 문서유형, 시행일, 생산일자, 적용대상
- 중복 제거: 문서번호, 제목, 생산일자, 관련 조문 조합으로 dedupe

## 5. Skill 3. 영향 후보 탐색 스킬

#### 역할

변경된 법령 조문과 기존 문서를 매칭해 변경 가능성이 있는 집행기준 후보를 뽑는다.

#### 입력

- Skill 1의 구조화된 법령 변경 데이터
- Skill 2의 기준문서 인덱스

#### 탐색 단계

1. 조문 직접 매칭
   - 문서의 `article_refs`가 변경 조문과 일치하는지 확인한다.

2. 키워드 매칭
   - 변경 조문의 핵심 용어와 문서의 제목/질의/회신/태그를 비교한다.

3. 요건 매칭
   - 납세자 유형, 거래 유형, 신고 절차, 공제 요건 등이 겹치는지 확인한다.

4. 의미 검색
   - 직접 조문번호가 없어도 동일 쟁점으로 보이는 문서를 벡터 검색으로 찾는다.

5. 시간 필터
   - 개정 전 생산된 문서 중 현재도 참조될 가능성이 있는 문서를 우선한다.

#### 영향 유형 분류

| 영향 유형 | 의미 |
|---|---|
| 직접 영향 | 변경 조문을 직접 인용하는 집행기준 |
| 요건 영향 | 조문번호는 다르지만 판단 요건이 바뀔 수 있음 |
| 절차 영향 | 신고, 제출, 세금계산서 발급 등 절차가 바뀔 수 있음 |
| 대상 영향 | 간이과세자, 영세사업자 등 적용 대상이 바뀔 수 있음 |
| 금액 기준 영향 | 기준금액, 공제한도, 면세기준 등 수치가 바뀜 |
| 낮은 관련성 | 키워드는 유사하지만 적용 요건이 다름 |

#### 점수화

```text
impact_score =
  조문 직접 일치 40점
  핵심 키워드 일치 20점
  납세자/거래 유형 일치 15점
  의미 검색 상위권 15점
  시행일/생산일자 관련성 10점
```

#### 출력

```json
{
  "change_id": "...",
  "candidate_doc_id": "...",
  "impact_type": "직접 영향",
  "impact_score": 87,
  "confidence": "높음|중간|낮음",
  "reason": "변경 조문을 직접 인용하고 간이과세자 적용 요건을 다룸",
  "matched_evidence": [
    "부가가치세법 제XX조",
    "해석례 문서번호 ...",
    "질의 본문 중 핵심 문장"
  ],
  "review_needed": true
}
```

## 6. Skill 4. 전문가 검토용 리포트 생성 스킬

#### 역할

영향 후보를 회계법인 임직원이 바로 검토할 수 있는 문서 형태로 정리한다.

#### 출력 형태

- 영향 후보 리스트
- 우선순위
- 관련 조문
- 관련 집행기준
- 왜 영향 가능성이 있는지
- 어떤 고객군에 영향을 줄 수 있는지
- 확인해야 할 쟁점
- 전문가 검토 필요 문구

#### 리포트 예시 구조

```text
1. 간이과세자 관련 해석례 영향 가능성 높음
   - 변경 조문: 부가가치세법 제XX조
   - 관련 문서: 국세청 해석례 XXX
   - 영향 이유: 기존 회신이 개정 전 요건을 전제로 함
   - 영향 고객: 간이과세 개인사업자
   - 확인 필요: 시행일 이후 거래분 적용 여부
   - 활용: 고객 안내문, 내부 체크리스트, Tax Agent 답변 가드레일
```

#### 내부문서용 버전

- 고객군별 영향
- 영업/홍보 소재
- 상담 유도 문구
- 검토 담당자 배정
- 후속 업데이트 필요 여부

#### Tax Agent 탑재용 버전

- 사용자 질문이 영향 후보와 관련될 때 경고 표시
- 단정 답변 대신 “개정 영향 검토 필요” 안내
- 회계법인 문의 또는 전문가 검토 연결
- 근거 조문과 해석례를 함께 표시

## 7. Skill 5. 검증·피드백 스킬

#### 역할

스킬이 실제로 쓸 만한 후보를 찾는지 작은 정답셋으로 검증한다.

#### 검증 데이터

과거 부가가치세 개정 사례 2~3개를 선정한다.

각 사례마다 아래 데이터를 준비한다.

```json
{
  "case_id": "vat_amendment_case_001",
  "amendment": "개정 조문 및 변경 요약",
  "known_affected_docs": ["실제로 영향받은 해석례 또는 집행기준"],
  "known_unaffected_docs": ["키워드는 비슷하지만 영향 없는 문서"],
  "expected_issue_tags": ["간이과세자", "세금계산서"],
  "review_memo": "왜 정답으로 보는지"
}
```

#### 평가 기준

| 지표 | 의미 |
|---|---|
| Recall | 실제 영향 문서를 후보에 올렸는가 |
| Precision | 관련 없는 문서를 너무 많이 올리지 않았는가 |
| Evidence Rate | 후보마다 조문/문서 근거가 붙었는가 |
| Review Usefulness | 전문가가 검토 우선순위를 잡을 수 있는가 |
| Safety Rate | 단정적 세무 자문을 피했는가 |

#### 검증 루프

1. 과거 개정 사례 입력
2. 영향 후보 자동 생성
3. 정답셋과 비교
4. 누락 후보 분석
5. 오탐 후보 분석
6. 태그/룰/검색 쿼리 수정
7. 다시 실행

#### 실패 유형 분류

- 조문번호 파싱 실패
- 시행일/적용례 누락
- 키워드 유사 오탐
- 납세자 유형 불일치
- 거래 유형 불일치
- 해석례 본문 chunk가 너무 작거나 큼
- 근거 없는 LLM 추정

## 8. 데이터 수집 계획

### 1단계. 최소 데이터

- 부가가치세법 개정 조문 2~3건
- 관련 신구조문대비표
- 부가가치세 집행기준 일부
- 부가가치세 집행기준 관련 기준/문단
- 세법해석정비 전후 해석례

### 2단계. 데모 데이터

- 간이과세자 관련 문서
- 세금계산서 관련 문서
- 매입세액공제 관련 문서
- 면세/과세 구분 관련 문서

### 3단계. 검증 데이터

- 과거 개정 이후 실제로 영향받은 해석례/집행기준 사례
- 키워드는 유사하지만 영향 없는 반례
- 전문가가 직접 표시한 검토 우선순위

## 9. 파싱 세부 계획

### 법령 파싱

- 조문번호 패턴: `제\\d+조`, `제\\d+조의\\d+`
- 항 패턴: `①`, `②`, `③` 또는 `(1)`, `(2)`
- 호 패턴: `1.`, `2.`, `가.`, `나.`
- 개정 유형 패턴: `신설`, `삭제`, `개정`, `종전`, `현행`
- 시행일 패턴: `시행일`, `적용례`, `경과조치`

### 해석례 파싱

- 문서번호
- 생산일자
- 제목
- 질의
- 회신
- 관련 법령
- 사실관계
- 판단 요지

### 집행기준 파싱

- 기준번호
- 제목
- 관련 조문
- 본문
- 예시
- 유의사항

### 1차 제외 문서

- 내부지침
- 기획재정부 해석
- 기본통칙
- 판례

## 11. 구현 방식

### 권장 아키텍처

```text
API 수집기
  -> 원문 저장소
  -> 파서
  -> 구조화 DB
  -> 검색 인덱스
  -> 영향 탐지 엔진
  -> LLM 요약기
  -> 리포트 생성기
  -> 검증 대시보드
```

### DB 구성

- `law_changes`
- `tax_documents`
- `document_chunks`
- `impact_candidates`
- `validation_cases`
- `review_feedback`

### 검색 구성

- 키워드 검색: 조문번호, 문서번호, 제목, 태그
- 벡터 검색: 집행기준 본문, 세법해석정비 전후 해석례
- 하이브리드 검색: 키워드 점수 + 벡터 점수 + 메타데이터 필터

### LLM 사용 위치

LLM은 판단을 독점하지 않고 아래 작업에만 사용한다.

- 변경 조문 요약
- 핵심 요건 추출
- 후보 문서와 변경 조문의 관련성 설명
- 전문가 검토 체크리스트 작성
- 고객군별 영향 메모 작성

LLM이 하지 말아야 할 일은 아래와 같다.

- 법령 유불리 최종 판단
- 절세 가능 여부 단정
- 근거 없는 해석례 변경 예측
- 출처 없는 답변 생성

## 12. Agent 탑재 시 응답 정책

사용자가 관련 질문을 하면 Tax Agent는 아래처럼 동작한다.

1. 질문이 영향 후보와 연결되는지 검색한다.
2. 연결되면 개정 영향 가능성을 표시한다.
3. 기존 해석례가 개정 전 법령을 전제로 할 수 있음을 알린다.
4. 조문, 해석례, 집행기준 근거를 제시한다.
5. 유불리 판단이나 신고 의사결정은 전문가 검토가 필요하다고 안내한다.

예시 문구:

```text
해당 쟁점은 최근 부가가치세법 개정 조문과 연결될 수 있어 기존 해석례를 그대로 적용하기 전에 검토가 필요합니다. 특히 시행일, 적용례, 거래시점에 따라 결론이 달라질 수 있으므로 회계법인 전문가 확인이 필요합니다.
```

## 13. 내부문서 활용 시 출력 정책

내부용 리포트는 아래 항목을 포함한다.

- 영향 가능성이 높은 쟁점 Top 10
- 고객군별 영향
- 영업/홍보 포인트
- 고객 안내문 초안
- 전문가 검토 필요 문서
- 변경 가능성이 높은 집행기준

## 14. 대회 제출용 구현 범위

### 반드시 구현

- 부가가치세 개정 조문 입력

- 영향 후보 추출

- 전문가 검토용 리스트 출력

- 실시간 법령 업데이트
- 모든 판례 반영
- 실제 신고 판단 자동화
- 완전한 법률 자문 문장 생성
