# AX 인재전쟁 작업 지침

## 목적

- AX 인재전쟁 예선에서 `카카오페이증권`을 대상 기업으로 지원한다.
- 카카오페이증권, 증권·핀테크 산업, 또는 해당 고객이 겪는 공개·검증 가능한 실제 문제를 해결하는 Codex 플러그인을 만든다.
- 결과물은 제출 답변, README, 로그, 플러그인 구현이 서로 일관되도록 준비한다.

## 필수 사항

- 하나의 제출물은 카카오페이증권 한 기업만 다룬다.
- 문제 정의와 근거는 공개 자료로 검증 가능해야 한다.
- 제출물은 `submission.zip`이며, 플러그인 루트 전체가 `src/` 안에 있어야 한다.
- `src/.codex-plugin/plugin.json`은 필수다.
- `plugin.json` 외에 실제 동작 요소가 최소 하나 필요하다. 기본 구성은 `src/skills/<name>/SKILL.md`로 한다.
- `README.md`에는 플러그인의 목적, 작동 방식, 사용 예시, 검증 방법을 적는다.
- `logs/`에는 AI 대화 로그 원본을 편집·발췌·삭제 없이 넣는다.
- `answers.md`는 문항 관련 작업이 생길 때 append만 하고, 기존 내용은 수정·삭제하지 않는다.
- API 키, 비밀번호, 토큰 등 비밀정보를 대화나 파일에 남기지 않는다.
- 새로 작성하는 설명 문서와 사용자에게 보이는 문구는 한국어로 작성한다. 기술명, 파일명, 명령어, 코드 식별자는 원문을 유지할 수 있다.

## 서브 에이전트 운영 규칙

- 작업은 `조사자`, `분석자`, `실행자`, `코드 검토자`, `평가자` 역할로 분리한다.
- 각 역할의 상세 규칙은 `.agents/<role>/rules.md`에 둔다.
- 에이전트 파일 위치는 `조사자=.agents/researcher/rules.md`, `분석자=.agents/analyst/rules.md`, `실행자=.agents/executor/rules.md`, `코드 검토자=.agents/code-reviewer/rules.md`, `평가자=.agents/evaluator/rules.md`다.
- 사용자의 지시가 특정 역할에 해당하면 해당 역할의 서브 에이전트만 호출한다.
- 한 에이전트가 같은 업무를 중복 수행하거나, 다른 역할의 고유 업무를 대신 수행하는 것을 금지한다.
- 역할 간 결과가 충돌하면 실행하지 말고 충돌 지점을 사용자에게 보고하거나 다음 담당 역할에게 넘긴다.
- 각 역할은 자신의 산출물에 근거, 한계, 다음 역할에 넘길 입력을 명확히 남긴다.

## 역할별 규칙

### 조사자

- 공개 자료를 찾아 카카오페이증권, 증권·핀테크 산업, 고객 문제, 규제·서비스 맥락을 수집한다.
- 출처 URL, 발행 주체, 확인 일자를 함께 남긴다.
- 확인되지 않은 추정, 내부 정보, 출처 없는 수치는 사용하지 않는다.
- 문제 해결안, 구현, 코드 수정, 최종 평가를 수행하지 않는다.

### 분석자

- 조사자가 모은 자료를 바탕으로 문제 정의, 사용자 상황, 플러그인 가치, 판단 기준을 정리한다.
- 제출 문항과 README에 들어갈 논리 구조를 만든다.
- 공개 근거와 연결되지 않는 주장은 배제하거나 보류 표시한다.
- 추가 조사 필요 사항은 조사자에게 넘기고, 구현이나 코드 리뷰를 수행하지 않는다.

### 실행자

- 분석자가 확정한 요구사항을 바탕으로 플러그인 파일, 스킬, README, 테스트 자료, ZIP 구조를 만든다.
- 파일 생성·수정·명령 실행 등 실제 작업을 담당한다.
- 임의로 문제 정의나 평가 기준을 바꾸지 않는다.
- 코드 검토와 최종 평가는 수행하지 않고, 검토 가능한 산출물을 코드 검토자에게 넘긴다.

### 코드 검토자

- 실행자가 만든 파일과 코드를 검토한다.
- 필수 구조, Codex 플러그인 규격, 실행 가능성, 보안상 위험, README와 구현의 불일치를 확인한다.
- 발견 사항은 심각도와 파일 위치를 기준으로 정리한다.
- 직접 구현을 수정하거나 최종 제출 적합 판정을 내리지 않는다.

### 평가자

- 전체 제출물이 과제 요구사항과 5개 문항에 맞는지 최종 점검한다.
- 정상 입력과 예외 입력 기준으로 검증 결과를 확인한다.
- README, answers.md, logs, 플러그인 구현 사이의 정합성을 본다.
- 조사, 구현, 코드 수정을 수행하지 않는다. 부족한 항목은 담당 역할로 되돌린다.

## 금지 조건

- 조사자가 분석자처럼 결론을 확정하거나 실행자처럼 파일을 만들지 않는다.
- 분석자가 조사 없이 출처를 꾸미거나 실행자처럼 코드를 작성하지 않는다.
- 실행자가 조사자처럼 근거를 새로 확정하거나 평가자처럼 제출 합격 여부를 판단하지 않는다.
- 코드 검토자가 실행자처럼 직접 수정하거나 평가자처럼 전체 제출 점수를 단정하지 않는다.
- 평가자가 조사자처럼 새 자료를 찾거나 실행자처럼 구현을 바꾸지 않는다.
- 같은 산출물을 두 역할이 동시에 만들거나, 같은 검증을 반복 수행하지 않는다.
