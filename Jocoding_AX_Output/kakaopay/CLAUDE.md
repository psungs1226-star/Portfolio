# AX 인재전쟁 MVP 계약

## 프로젝트

- 대상 기업: `카카오페이증권`
- 현재 단계 묶음: `0-mvp-schd-frontend`
- 제품 방향: 해외 ETF 모으기 과거 시뮬레이션 기반 리스크 설명 UX
- 제출 루트: `submission/`
- Codex 플러그인 루트: `submission/src/`

## 운영 규칙

- `agents.md`와 `.agents/<role>/rules.md`를 따른다.
- 역할은 `조사자`, `분석자`, `실행자`, `코드 검토자`, `평가자`로 분리한다.
- 현재 구현 범위는 실행자 작업이다. 사용자가 명시적으로 분석자 단계로 되돌리지 않는 한 문제 정의를 다시 바꾸지 않는다.
- `answers.md`는 append만 하고 기존 내용을 수정하거나 삭제하지 않는다.
- API 키, 비밀번호, 토큰, 실제 계좌정보, 개인 투자정보를 파일이나 대화에 남기지 않는다.
- 새로 작성하는 문서와 사용자에게 보이는 문구는 한국어로 작성한다. 기술명, 파일명, 명령어, 코드 식별자는 원문을 유지할 수 있다.

## 고정 문제 정의

카카오페이증권의 해외 ETF 모으기 확장 과정에서, 사용자가 과거 수익률을 미래 성과로 오해하지 않도록 과거 적립 시뮬레이션의 결과 범위, 손실 가능성, 환율, 수수료, 세금 영향을 모바일 UX로 설명한다.

## 제품 범위

- SCHD는 고정 예시 데이터일 뿐이며, 홍보 대상 상품이 아니다.
- MVP는 실시간 증권 API를 사용하지 않는다.
- MVP는 개인 투자정보를 요구하지 않는다.
- MVP는 주문 제출, 자동 매매, 세무 대리 기능을 제공하지 않는다.
- 출력은 투자 행동 안내가 아니라 과거 데이터 기반 설명과 시나리오 검토로 제한한다.

## 표현 금지 규칙

아래 표현은 제품 주장, CTA 라벨, 결과 라벨, 사용자 행동 유도 문구로 사용하지 않는다.

- `예상 수익률`
- `95% 확률`
- `추천`
- `안정적`
- `초보자에게 적합`
- `장기적으로 유리`

모든 결과 화면에는 아래 의미가 드러나야 한다.

- 과거 데이터 기준
- 가정 기반 시뮬레이션
- 미래 성과 아님

## 기술 범위

- 웹 MVP 위치: `submission/src/web/`
- 기술 스택: Vite, React, TypeScript
- 데이터: 로컬 고정 예시 데이터만 사용
- 계산: 로컬 결정론적 함수로 처리
- 네트워크: 런타임 외부 호출 없음
- 테스트 대상: 계산 모듈이 생긴 뒤 빌드와 집중 단위 테스트 수행

## 단계별 승인 게이트

- 0단계는 이 계약 문서와 `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/ADR.md`를 만든다.
- 1단계는 사용자가 문제 정의를 승인한 뒤 시작한다.
- 2단계는 사용자가 UX 흐름을 승인한 뒤 시작한다.
- 4단계는 사용자가 SCHD 고정 예시 데이터 사용 범위를 승인한 뒤 시작한다.
- 6단계는 사용자가 결과 화면을 승인한 뒤 시작한다.
- ZIP 생성은 사용자의 최종 제출 승인 뒤 진행한다.
