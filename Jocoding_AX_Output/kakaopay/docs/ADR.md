# ADR: MVP 방향과 제약

## 상태

0단계 계약 기준으로 채택한다.

## 맥락

제출물은 `카카오페이증권` 한 기업을 대상으로 해야 하며, 공개적으로 검증 가능한 문제를 Codex 플러그인으로 해결해야 한다. 기존 조사와 단계 계획은 MVP 방향을 해외 ETF 모으기 과거 시뮬레이션 리스크를 설명하는 모바일 UX로 고정했다.

앞선 후보에는 컴플라이언스 체크리스트 도구, 세제 시나리오 계산기, 투자정보 해석 도구가 포함되어 있었다. 현재 단계 묶음은 소비자보호 가치를 직접 보여줄 수 있고 내부 데이터 의존이 낮은 프론트엔드 MVP와 Codex 스킬로 범위를 좁힌다.

## 결정

`submission/src/web/` 아래에 Vite, React, TypeScript, 로컬 고정 예시 데이터 기반의 모바일 우선 웹 MVP를 만든다. MVP는 SCHD를 고정 예시 데이터로만 사용하고, 모든 출력은 과거 데이터 기반 시나리오 설명으로 제한한다.

`submission/src/` 아래의 Codex 플러그인은 리스크 우선 설명 UX를 검토하고 생성하는 스킬을 포함한다. README와 제출 답변은 같은 문제, 제약, 검증 흐름을 설명한다.

## 결과

- 외부 API 없이 MVP를 만들고 검증할 수 있다.
- 제출물은 텍스트 체크리스트가 아니라 실제 작동 화면을 보여줄 수 있다.
- 소비자보호형 문제 정의와 충돌하지 않는다.
- 금융 주제이므로 문구가 투자 조언이나 성과 약속처럼 보이지 않게 관리해야 한다.

## 기각한 선택지

### 실시간 증권 데이터 연동

인증정보, 개인 데이터 처리, 내부 시스템 가정이 필요하므로 제외한다.

### 상품 순위화 또는 투자 행동 안내

투자 조언으로 읽힐 수 있고 소비자보호 목표와 맞지 않아 제외한다.

### 단순 컴플라이언스 안내 체크리스트

이번 MVP는 문서 누락 검수가 아니라 설명형 시뮬레이션 UX이므로 제외한다.

### 데스크톱 대시보드 우선 구현

목표 경험이 모바일 금융 앱 흐름이므로 제외한다.

## 가드레일

- 로컬 고정 예시 데이터만 사용한다.
- 결과 옆에 가정을 함께 보여준다.
- 우호적 결과보다 리스크와 비용 영향을 먼저 보여준다.
- 상품 권유, 확실성, 미래 결과를 암시하는 표현을 피한다.
- 비밀정보나 개인 금융정보를 만들거나 저장하지 않는다.
- 새 문서는 한국어로 작성하고, 기술명과 파일명만 필요한 경우 원문을 유지한다.

## 0단계 검토 인계

코드 검토자는 아래 항목을 확인한다.

- 0단계 필수 파일이 존재한다.
- 문서가 투자 행동을 유도하는 표현을 허용하지 않는다.
- 기술 스택이 Vite, React, TypeScript, 로컬 고정 예시 데이터 계산으로 제한되어 있다.
- 제출 경로는 `submission/` 아래에 유지되고, 플러그인 루트는 `submission/src/`로 유지된다.
