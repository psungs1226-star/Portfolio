# UX: 모바일 리스크 설명 명세

## Step 1 목적과 범위

이 문서는 `0-mvp-schd-frontend`의 Step 1 산출물로, 해외 ETF 모으기 과거 시뮬레이션 기반 리스크 설명 UX의 모바일 앱형 흐름을 정의한다. 목표는 사용자가 과거 적립 결과를 미래 성과로 오해하지 않도록 입력 조건, 가정, 결과 범위, 불리한 구간, 비용 영향을 순서대로 확인하게 하는 것이다.

범위는 `submission/src/web/`에서 구현할 화면 구조와 컴포넌트 상태 명세로 제한한다. 새 조사, 문제 정의 변경, 계산 로직 구현, README 또는 제출 답변 작성은 이 문서의 범위가 아니다. SCHD는 고정 예시 데이터로만 다루며, 모든 결과 화면은 `과거 시뮬레이션 · 미래 성과 아님` 의미를 드러내야 한다.

## UX 원칙

- 모바일 첫 화면은 분석 조건 확인에 집중한다.
- 결과 첫 화면은 우호적 결과보다 불리한 사례, 원금 하회 구간, 최대낙폭, 비용 영향을 먼저 이해시키는 구조를 따른다.
- 통계 용어는 기본 화면에서 최소화하고 상세 수치는 접힌 영역에 둔다.
- 입력값은 투자 지시가 아니라 시뮬레이션 가정으로 표현한다.
- CTA는 주문, 매수, 종목 선택, 투자 실행을 떠올리게 하지 않는 확인형 문구를 쓴다.
- 모든 화면은 390px 모바일 폭에서 텍스트, 숫자, 그래프 라벨이 겹치지 않아야 한다.

## 모바일 앱형 UX 흐름

### 1. 입력 화면

목적은 사용자가 시뮬레이션 조건을 빠르게 확인하고 필요할 때만 값을 조정하게 하는 것이다.

- 상단 고지: `고정 예시 데이터 · 과거 기준`
- 기본 입력:
  - 분석 대상 ETF: `SCHD`
  - 적립 금액: `매일 5,000원`
  - 기간: `5년`
  - 표시 기준: `원화 기준`
- 고급 설정은 접힌 상태로 시작한다.
  - 환율 반영 방식
  - 수수료 가정
  - 세금 가정
  - 배당 재투자 가정
- 기본 CTA 라벨:
  - `분석 조건 확인`
  - `가정 보기`
  - `결과 범위 보기`

입력 화면에서는 수익을 암시하는 카피를 두지 않는다. 사용자가 보는 핵심 행동은 조건 확인이며, 투자 실행으로 오해될 수 있는 버튼은 만들지 않는다.

### 2. 가정 확인

목적은 결과가 특정 가정과 과거 데이터에 묶여 있음을 결과 전에 인지시키는 것이다.

- 입력값 요약을 한 줄 단위로 보여준다.
- 고급 설정 값은 `적용된 가정` 영역에 모아 표시한다.
- 각 가정 옆에는 짧은 설명을 둔다.
  - 환율: 원화 표시 결과에 영향을 줄 수 있음
  - 수수료: 누적 결과에서 차감되는 비용으로 반영
  - 세금: 예시 규칙에 따른 차감 항목으로 반영
  - 배당 재투자: 고정 가정에 따른 비교 항목으로 반영
- 하단 고지:
  - `이 화면의 값은 과거 데이터와 명시된 가정으로 계산됩니다.`
  - `미래 성과를 뜻하지 않습니다.`

### 3. 결과 첫 화면

목적은 숫자 하나가 아니라 결과 범위와 불리한 구간을 먼저 보게 하는 것이다.

표시 순서는 아래를 기본으로 한다.

1. 고지 라벨: `과거 시뮬레이션 · 미래 성과 아님`
2. 한 줄 해석: 불리한 구간과 비용 영향을 쉬운 문장으로 설명
3. 총 원금
4. 중간 사례
5. 불리한 사례
6. 최대낙폭과 쉬운 풀이 라벨
7. 비용 영향 보조 요약 라벨
8. `가정 다시 보기` 보조 CTA
9. `그래프 자세히 보기` 보조 CTA

결과 첫 화면의 주요 숫자는 총 원금, 중간 사례, 불리한 사례, 최대낙폭 4개로 제한한다. 비용 영향은 주요 숫자로 추가하지 않고, 4개 주요 숫자 아래 또는 근처에 짧은 보조 요약 라벨로 우선 노출한다. `최대낙폭`은 용어만 단독으로 쓰지 않고, 옆에 `가장 크게 내려갔던 구간`처럼 초보자용 쉬운 풀이 라벨을 함께 붙인다. 우호적 사례는 기본 노출 항목이 아니라 `그래프 자세히 보기` 또는 `자세한 수치` 접힘 영역에서 보조 항목으로 확인하게 한다. 결과 카드는 한 화면에 너무 많은 수치를 넣지 않으며, 불리한 사례와 최대낙폭을 먼저 읽을 수 있게 배치한다.

### 4. 그래프 상세

목적은 결과 숫자의 배경을 시각적으로 확인하게 하는 것이다. 기본 그래프는 3개로 제한한다.

- 원금 대비 평가금액
  - 원금선과 평가금액선을 함께 표시한다.
  - 원금 하회 구간은 면 또는 라벨로 짧게 표시한다.
- 과거 결과 범위 밴드
  - 단일 결과가 아니라 구간별 차이를 보여준다.
  - 기본 화면에는 복잡한 통계 라벨을 노출하지 않는다.
  - 우호적 사례는 이 그래프 또는 `자세한 수치` 접힘 영역에서 보조 항목으로 표시한다.
- 환율, 수수료, 세금 영향 비교
  - 비용 반영 전후 차이를 막대 또는 단순 비교 카드로 보여준다.
  - 비용 영향은 투자 판단 문구가 아니라 계산 가정 설명으로 표시한다.

상세 통계, 기간별 값, 원자료 메모는 `자세한 수치` 접힘 영역에 둔다.

### 5. 위험 설명

목적은 사용자가 결과를 성과 약속이 아니라 과거 사례 설명으로 이해하게 하는 것이다.

- 결과 아래에 항상 짧은 위험 설명을 둔다.
- 설명 항목:
  - 과거 데이터 기준이라는 점
  - 같은 적립 조건에서도 시작 시점에 따라 결과가 달라질 수 있다는 점
  - 환율, 수수료, 세금 가정이 원화 결과에 영향을 준다는 점
  - SCHD는 고정 예시 데이터이며 상품 권유가 아니라는 점
- 긴 설명은 접힌 영역에 두되, 기본 화면에서도 핵심 고지는 보여야 한다.

### 6. 오류 상태

목적은 입력 오류나 계산 불가 상태에서도 투자 실행 화면처럼 보이지 않게 안내하는 것이다.

- 빈 금액: `적립 금액을 입력해 주세요.`
- 0원 이하: `0원보다 큰 금액을 입력해 주세요.`
- 지원하지 않는 기간: `이 예시 데이터에서 확인 가능한 기간으로 바꿔 주세요.`
- 계산 실패: `현재 조건으로 결과를 표시할 수 없습니다. 입력값과 가정을 다시 확인해 주세요.`
- 데이터 없음: `표시할 예시 데이터가 없습니다.`

오류 CTA는 `입력 다시 확인`, `가정 다시 보기`처럼 복구 행동으로 제한한다.

## 390px 모바일 폭 기준 원칙

- 한 화면의 주요 숫자는 3~4개를 넘기지 않는다.
- 비용 영향은 주요 숫자 수에 포함하지 않는 짧은 보조 요약이나 라벨로 노출한다.
- 결과 첫 화면의 카드 제목은 1줄, 설명은 2줄 이내를 목표로 한다.
- 본문 문장은 16px 기준으로 읽히게 하고, 보조 설명은 13~14px 범위에서 사용한다.
- 그래프 높이는 최소 180px을 확보하되, 축 라벨이 본문을 밀어내지 않게 한다.
- 그래프 범례는 상단 또는 하단 한 줄로 두고, 긴 항목은 줄바꿈한다.
- 좌우 padding은 16px을 기본으로 하고, 카드 내부 padding은 14~16px 범위로 둔다.
- 긴 금액은 줄바꿈 가능한 단위로 표시한다.
- 접힌 상세 영역은 기본 흐름을 밀어내지 않게 하며, 펼쳤을 때도 CTA와 겹치지 않아야 한다.
- 색상만으로 손실 구간이나 비용 영향을 전달하지 않고, 짧은 라벨을 함께 둔다.
- 버튼은 엄지 조작을 고려해 높이 44px 이상을 확보한다.

## CTA 라벨 원칙

CTA는 투자 실행을 유도하는 인상을 주지 않는 확인형, 탐색형 문구로 작성한다.

사용 가능한 방향:

- `분석 조건 확인`
- `가정 보기`
- `결과 범위 보기`
- `그래프 자세히 보기`
- `입력 다시 확인`
- `가정 다시 보기`

피해야 할 방향:

- 주문, 매수, 가입, 선택 완료처럼 금융 실행을 떠올리게 하는 문구
- 성과를 기대하게 하는 문구
- 특정 상품을 고르게 만드는 문구
- 다음 행동을 투자 판단으로 연결하는 문구

금지 표현은 제품 주장, CTA, 결과 라벨, 사용자 행동 유도 문구에서 사용하지 않는다. 금지 표현 목록은 `예상 수익률`, `95% 확률`, `추천`, `안정적`, `초보자에게 적합`, `장기적으로 유리`이다.

## 코드 검토자에게 넘길 확인 항목

- `docs/UX.md`가 Step 1 Acceptance Criteria를 충족하는지 확인한다.
- 화면 흐름이 구현 가능한 컴포넌트 단위로 나뉘어 있는지 확인한다.
- 390px 모바일 폭 기준으로 정보량, 텍스트 길이, 그래프 개수가 과하지 않은지 확인한다.
- CTA 라벨이 투자 실행을 유도하는 문구로 보이지 않는지 확인한다.
- 금지 표현이 금지 목록 설명 외의 제품 주장, CTA, 결과 라벨, 사용자 행동 유도 문구에 쓰이지 않았는지 확인한다.

## 평가자에게 넘길 확인 항목

- 전체 흐름이 `수익률 계산기`가 아니라 리스크 설명 UX로 읽히는지 확인한다.
- 처음 이용하는 사용자가 통계 용어 없이 핵심 의미를 이해할 수 있는지 확인한다.
- 결과 첫 화면에서 불리한 사례, 최대낙폭, 비용 영향이 우선적으로 보이는지 확인한다.
- SCHD가 고정 예시 데이터로만 설명되고 상품 권유처럼 읽히지 않는지 확인한다.
- PRD, ADR, phase review plan의 문제 정의와 이 UX 명세가 충돌하지 않는지 확인한다.
