### 앱인토스 7월 바이브코딩 챌린지 — "미니앱과 함께하는 여름"

작성일: 2026년 7월 6일 · 마감까지 D-23 (첫 빌드 제출 7/29)

---

## 1. 한눈에 보기

여름 대표곡을 무드·연도별로 큐레이션하고, 각 곡을 **공식 유튜브 링크로 바로 연결**해주는 미니앱이다. 토스 미니앱은 음원을 자체 스트리밍할 수 없으므로, 앱인토스 SDK의 `openURL`로 유튜브 앱/브라우저를 열어 재생을 위임하는 구조가 핵심이자 규정상 가장 안전한 방식이다.

핵심 컨셉은 세 가지 진입 경험을 한 앱에 통합한다.

- **무드/상황별 큐레이션** — 바다, 드라이브, 밤바다, 물놀이, 여름밤 감성 등 상황 플레이리스트
- **연도별 여름 히트곡** — 역대 여름 시즌송을 연도별로 모아 추억을 자극
- **오늘의 여름노래** — 매일 한 곡을 추천해 재방문을 유도 (지표 심사 대비 핵심 장치)

> 왜 이 컨셉이 유리한가: 1차 심사가 8/1~8/26 **지표 종합 평가**이므로, 단발성 소비가 아닌 *재방문·체류·공유*를 만드는 구조가 중요하다. "오늘의 곡"(재방문) + "공유"(유입) + "즐겨찾기"(리텐션)가 이 세 축을 직접 겨냥한다.

### 메인 타겟: 20~30대 여성 중심 (고정)

서비스의 핵심 사용자는 **20~30대 여성 중심**이다. 큐레이션·디자인·문구를 전부 이 타겟 기준으로 맞춘다.

- **큐레이션 가중치**: 20~30대 여성 중심 타겟이 10대·20대에 듣던 **2000년대 후반 ~ 2020년대** 곡 중심. 7080·8090 클래식은 "타임리스 명곡"만 소량으로.
- **연도별 축("그 해 여름")**: 이 세대의 추억 구간인 **2012~2024 시즌송**을 두텁게 구성.
- **디자인·문구**: 트렌디·미니멀 톤(현행 액센트 원톤 유지), 캐주얼하되 유치하지 않게.
- **지표 연결**: SNS 공유·데일리 추천이 20~30대 여성 중심 타겟의 음악 소비 습관과 맞물려 재방문·유입 지표에 유리.

## 4. 기술 스택 & 아키텍처

### 4-1. 스택 결정

| 구분 | 선택 | 근거 |
| --- | --- | --- |
| 개발 방식 | **WebView + React (Vite)** | 바이브코딩에 가장 빠름. `create-ait-app` 기본 경로, `openURL` 웹 프레임워크 지원 |
| 프로젝트 생성 | `npx create-ait-app {appName}` | `npm` + `react-ts` + TDS 사용 `Y`, 불필요한 샘플 기능 제외 |
| 디자인 | **TDS (Toss Design System)** + 비게임 내비게이션 바 | 심사 통과 및 통일감 |
| 렌더링 | **CSR 또는 SSG만** (SSR 금지) | 출시 정책 필수 요건 |
| 데이터 | 정적 JSON 번들(곡 메타데이터) | 서버 불필요, SSG 친화적, 링크 깨짐 관리 용이 |
| 외부 연결 | `openURL('https://youtu.be/...')` (`@apps-in-toss/web-framework`) | 유튜브 앱/브라우저로 재생 위임 |
| 저장 | `Storage` API | 즐겨찾기·최근 본 곡을 앱 재접속 후에도 유지 |
| 지표 | `Analytics`(사용자 행동), `referrer`(유입경로) | 1차 지표 심사 대비 |
| 공유 | `getTossShareLink` / `share` | 곡·플레이리스트 공유로 신규 유입 |

### 4-2. 개발 환경 세팅 (바이브코딩)
1. Node.js + VS Code 설치
2. AI 도구는 현재 작업 환경에 맞게 Codex/Claude 등으로 선택
3. 앱인토스 MCP 설치·연결: `brew tap toss/tap && brew install ax` 후 사용 도구별 MCP 연결 명령 적용
4. 공식 문서 검색 도구 또는 MCP를 활용해 Apps in Toss API 사용법 확인
5. `npx create-ait-app {appName}` → `npm`, `react-ts`, TDS `Y` 선택
6. `granite.config.ts`에 appName·displayName·primaryColor·icon 입력. icon은 콘솔 업로드 URL 확보 전까지 Phase 6 확인 항목으로 관리

### 4-3. 데이터 모델 (예시)
```
{
  "id": "S001",
  "title": "How Sweet",
  "artist": "NewJeans",
  "year": 2024,
  "mood": "상큼발랄",
  "moments": ["바다", "드라이브"],
  "group": "여돌",
  "videoId": "Q3K0TOvTOno"
}
```
"오늘의 여름노래"는 **날짜 시드 기반 결정 함수**(예: 날짜→index)로 서버 없이 매일 다른 곡을 노출한다.
유튜브 URL, 유튜브뮤직 URL, 썸네일 URL은 `videoId`에서 런타임에 파생한다.

## 5. 저작권 & 정책 리스크 대응 (음악 앱 핵심)

음악을 다루므로 저작권 관리가 심사·출시의 최대 리스크다.

- **음원 자체 재생·스트리밍 금지** → 반드시 유튜브로 링크 연결만 (호스팅 X)
- **공식 채널 링크만 큐레이션** → 아티스트/레이블 공식 채널, 공식 MV, 아티스트 'Topic' 채널만 사용. 불법 재업로드 링크는 배제(링크 깨짐·저작권 리스크 동시 해결)
- **썸네일·앨범아트** → 임의 앨범아트 대신 유튜브 공식 썸네일(`img.youtube.com/vi/...`) 사용 또는 자체 디자인 그래픽. 저작권 있는 이미지 직접 사용 지양
- **텍스트 메타데이터**(곡명·아티스트·연도)는 사실 정보로 사용 가능
- 출시 전 [저작권 침해 신고 가이드] 재확인, 문제 소지 링크는 즉시 교체 운영

> 포지셔닝 메모: 이 앱은 "음원 서비스"가 아니라 **여름노래 큐레이션·발견 도구**다. 공식 유튜브로 연결하는 것이 유일한 재생 경로임을 UX와 신청폼 설명에 명시한다.

## 11. Build Harness: MVP → 완제품

완제품까지 한 번에 크게 만들지 않고, 각 phase마다 "검증 가능한 산출물"을 만든 뒤 다음 단계로 넘어간다.

상세 업무 문서는 `docs/phases/` 아래에 phase별로 분리한다. phase 검수는 `reviewer_agents.md`의 `summer-song-phase-reviewer`(`gpt-5.4-mini`) 기준을 따른다.

### Phase 0. 콘솔/브랜딩 준비

**목표**: 앱 등록과 심사 입력에 필요한 기본 자산을 확정한다.

| Step | 작업 | 완료 조건 |
| --- | --- | --- |
| 0-1 | 앱 이름/appName 확정 | 앱 이름 `오늘의 여름노래`, appName `summer-song` |
| 0-2 | 앱 가치/상세설명 작성 | 콘솔 입력 가능한 20자 가치 문구와 상세설명 확보 |
| 0-3 | 로고/썸네일 제작 | 로고 600×600, 썸네일 1932×828 준비 |
| 0-4 | 검색 키워드 정리 | 콘솔 입력용 핵심 키워드 10~15개 확보 |

**Gate**: 콘솔 앱 등록 가능 상태.

상세 문서: `docs/phases/phase-0-console-branding.md`

### Phase 1. MVP 데이터 하네스

**목표**: 전체 300곡 검증 전에, 화면과 링크 동작을 확인할 최소 데이터만 만든다.

| Step | 작업 | 완료 조건 |
| --- | --- | --- |
| 1-1 | MVP 곡 20곡 선별 | 무드 4종, 순간 4종, 2010년대/2020년대가 모두 포함됨 |
| 1-2 | 공식 videoId 채우기 | 20곡 모두 공식 MV/Topic/소속사 채널 링크 확인 |
| 1-3 | 앱용 JSON 생성 | `songs.json`에 id/title/artist/year/mood/moments/group/videoId 포함 |
| 1-4 | 링크 파생 로직 확인 | `youtu.be`, `music.youtube.com`, 썸네일 URL이 videoId에서 생성됨 |

**Gate**: 20곡으로 모든 화면 상태와 외부 링크를 테스트할 수 있음.

상세 문서: `docs/phases/phase-1-mvp-data-harness.md`

### Phase 2. MVP 앱 구현

**목표**: 핵심 사용 흐름이 실제 앱에서 끝까지 동작한다.

| Step | 작업 | 완료 조건 |
| --- | --- | --- |
| 2-1 | 프로젝트 생성 | `npx create-ait-app summer-song`, `npm` + `react-ts` + TDS 선택 |
| 2-2 | 기본 설정 | `granite.config.ts`에 appName/displayName/primaryColor 반영, icon은 콘솔 URL 확보 시 반영 |
| 2-3 | 홈 구현 | 오늘의 여름노래 카드, 주요 CTA, 무드 진입 노출 |
| 2-4 | 무드/순간 리스트 구현 | 태그별 곡 리스트 필터링 |
| 2-5 | 연도별 리스트 구현 | 연도 선택 시 해당 곡 노출 |
| 2-6 | 외부 링크 연결 | 유튜브/유튜브뮤직 버튼이 `openURL`로 동작 |
| 2-7 | 찜 진입점 | 하단 탭과 찜 없음 상태 표시, 저장 기능은 Phase 3에서 구현 |
| 2-8 | 기본 반응형 확인 | 모바일 WebView 기준 레이아웃 깨짐 없음 |

**Gate**: 20곡 데이터로 "탐색 → 곡 선택 → 유튜브 열기"가 끊기지 않음.

상세 문서: `docs/phases/phase-2-mvp-app-implementation.md`

### Phase 3. MVP 품질 보강

**목표**: 심사에서 "단순 링크 모음"으로 보이지 않도록 앱 경험을 완성한다.

| Step | 작업 | 완료 조건 |
| --- | --- | --- |
| 3-1 | 오늘의 곡 날짜 로직 | 날짜 시드 기반으로 매일 다른 곡 노출 |
| 3-2 | 찜하기 | Storage에 저장/해제/목록 유지 |
| 3-3 | 썸네일 폴백 | 이미지 로딩 실패 시 컬러 타일로 대체 |
| 3-4 | 빈 상태/오류 상태 | 찜 없음, 링크 없음, 이미지 실패 상태 처리 |
| 3-5 | UX 문구 정리 | 공식 영상 연결 안내, 과한 설명 제거 |
| 3-6 | 타겟 UX/비주얼 디벨롭 | 20~30대 여성 중심 타겟 기준으로 첫 화면, 카테고리, 찜 UX 보강 |
| 3-7 | 이미지 자산 판단 | 공식 YouTube 썸네일 우선, 필요 시 생성 이미지로 폴백/빈 상태/콘솔 보조 그래픽 보강 |

**Gate**: 사용자가 재방문/저장할 이유가 생기고, 단순 링크 목록처럼 보이지 않음.

상세 문서: `docs/phases/phase-3-mvp-quality-hardening.md`

### Phase 4. 데이터 확장

**목표**: MVP 20곡에서 출시용 큐레이션으로 확장한다.

| Step | 작업 | 완료 조건 |
| --- | --- | --- |
| 4-1 | 300곡 중 우선 검증분 선정 | 상위 80~120곡 우선순위 확정 |
| 4-2 | 공식 링크 검증 | 공식 MV/Topic/소속사 채널만 채택 |
| 4-3 | 중복/부적합 제거 | 계절감 약한 곡, 비공식 링크, 깨진 링크 제외 |
| 4-4 | JSON 재생성 | 검증 완료 곡만 앱 데이터에 포함 |
| 4-5 | 카테고리 균형 확인 | 무드/순간/연도별 리스트가 빈약하지 않음 |
| 4-6 | 연도별 보강 | 2012~2024 구간이 20~30대 여성 중심 타겟의 추억/최신감 기준으로 충분히 채워짐 |

**Gate**: 출시 후보 데이터가 정책 리스크 없이 동작함.

상세 문서: `docs/phases/phase-4-data-expansion.md`

### Phase 6. QA/출시

**목표**: 정책 위반과 기본 동작 오류 없이 첫 빌드를 제출한다.

| Step | 작업 | 완료 조건 |
| --- | --- | --- |
| 6-1 | 정책 체크 | SSR/eval/강제유도/비공식 링크/저작권 리스크 점검 |
| 6-2 | 기기 테스트 | 샌드박스, 모바일 화면, 뒤로가기/닫기 동작 확인 |
| 6-3 | 성능 확인 | 첫 화면 로딩, 이미지 lazy loading, 2초 이상 지연 없음 |
| 6-4 | 빌드 | `npm run build` 성공 |
| 6-5 | 콘솔 업로드 | `.ait` 번들 등록, 아이콘 URL과 `brand.icon` 일치 확인 |
| 6-6 | 디자인 QA | 20~30대 여성 타겟 적합성, 이미지 자산 정책 리스크, 모바일 캡처 확인 |
| 6-7 | 신청폼 제출 | 앱 이름, appName, 소개, 주제 연관성 일치 |

**Gate**: 7/29 전 첫 앱 번들 제출 완료.
