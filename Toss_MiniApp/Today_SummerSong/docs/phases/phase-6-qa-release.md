# Phase 6. QA/출시

## 목표

정책 위반과 기본 동작 오류 없이 7/29 전 첫 앱 번들을 제출한다.

## 작업

1. 출시 정책을 점검한다.
   - CSR/SSG만 사용
   - SSR 없음
   - `eval` 없음
   - `window.location.replace` 없음
   - 자동 바텀시트/강제 행동 유도 없음
2. 외부 링크 정책을 점검한다.
   - 유튜브/유튜브뮤직 링크는 `openURL` 사용
   - 공식 링크만 포함
   - 비공식 재업로드 없음
3. 모바일 화면 QA를 진행한다.
   - 홈
   - 무드/순간
   - 연도
   - 곡 상세 또는 곡 카드
   - 찜 목록
4. 내비게이션을 확인한다.
   - 뒤로가기
   - 닫기
   - 최초 화면 종료 동작
5. 성능을 확인한다.
   - 첫 화면 로딩
   - 이미지 lazy loading
   - 2초 이상 멈춤 없음
6. 빌드한다.
   - `npm run build`
   - `.ait` 번들 생성
   - 번들 생성 경로와 파일명을 QA 메모에 기록
7. 콘솔에 업로드한다.
   - 콘솔 업로드 후 발급/확정된 아이콘 URL이 있으면 `granite.config.ts`의 `brand.icon`과 제출 정보 일치 확인
8. 디자인/이미지 QA를 진행한다.
   - 20~30대 여성 중심 타겟에 맞는 톤인지 확인
   - 홈 첫 화면에서 오늘의 곡 CTA가 가장 먼저 읽히는지 확인
   - 무드/순간/연도/찜 화면이 단순 링크 목록처럼 보이지 않는지 확인
   - 공식 YouTube 썸네일, 생성 이미지, 콘솔 자산 사용 근거를 확인
   - 저작권 있는 앨범아트/사진이 임의로 번들에 들어가지 않았는지 확인
9. 신청폼을 제출한다.
   - 앱 이름 일치
   - appName 일치
   - 한줄 소개 일치
   - 챌린지 주제 연관성 명확

## QA 테스트 매트릭스

| 영역 | 테스트 항목 | 통과 기준 | 증거 |
| --- | --- | --- | --- |
| 홈 | 오늘의 곡 표시 | 곡명/아티스트/CTA가 겹치지 않음 | 모바일 스크린샷 |
| 홈 | 오늘의 곡 CTA | 유튜브/유튜브뮤직 버튼이 `openURL`로 동작 | 테스트 로그 |
| 무드/순간 | 필터 진입 | 각 카테고리 리스트가 표시됨 | 스크린샷 |
| 연도 | 연도 선택 | 해당 연도 곡만 표시됨 | 스크린샷 |
| 찜 | 저장/해제 | 재접속 후 찜 상태 유지 | 테스트 메모 |
| 썸네일 | 이미지 실패 | 폴백 타일 표시 | 강제 실패 캡처 |
| 내비게이션 | 뒤로가기 | 이전 화면 또는 앱 종료가 의도대로 동작 | 테스트 메모 |
| 성능 | 첫 화면 | 체감 2초 이상 멈춤 없음 | 실행 로그 |
| 정책 | 외부 링크 | `openURL` 외 직접 이동 없음 | 코드 검색 결과 |
| 정책 | 금지 패턴 | SSR/eval/window.location.replace 없음 | 코드 검색 결과 |
| 디자인 | 타겟 적합성 | 20~30대 여성 중심 타겟에 맞는 톤과 밀도 | 홈/리스트/찜 캡처 |
| 이미지 | 자산 리스크 | 공식 썸네일 또는 생성 이미지 사용 근거가 명확함 | 자산 목록/검토 메모 |

- 무드/순간 리스트 스크린샷

- 유튜브뮤직 CTA 동작 확인 메모
- `npm run build` 결과
- `.ait` 번들 파일 경로
- 금지 패턴 검색 결과
  - `rg "eval\\("`
  - `rg "window\\.location\\.replace"`
  - SSR 관련 설정 검색 결과
- 외부 링크 구현부 코드 위치
- 디자인 타겟 적합성 검토 메모

- 신청폼 제출 여부

리뷰어는 다음을 확인한다.

- 출시 정책 위반 가능성이 없는가
- 링크/저작권 리스크가 남아 있지 않은가

- QA 증거가 실제 산출물로 남아 있는가
