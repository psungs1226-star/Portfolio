# Evry Times — PRD (Product Requirements Document)

> 앱 이름: **Evry Times** (appName `evrytimes`). "every time" — 매 순간/매일 여는 데일리 홈.

> 앱인토스 바이브코딩 챌린지 출품작. 기획 원안(v0.1)은 본 문서로 대체됐다.
> 함께 보기: [ARCHITECTURE.md](./ARCHITECTURE.md) · [TECH_STACK.md](./TECH_STACK.md)

## 1. 배경 / 문제
매일 아침 날씨·운세·D-day는 앱을 따로 켜서 확인하고, 메모·일기는 또 다른 앱에 흩어져 기록한다. 이 "흩어짐"이 일상의 작은 마찰이다. → **"오늘"이라는 단일 축에 확인거리와 기록거리를 한 홈으로 모은 개인화 대시보드**로 해소한다.

## 2. 목표 / 컨테스트 컨텍스트
- **출품 대상:** 앱인토스 바이브코딩 챌린지, 주제 **"일상이 편해지는 순간"**(정보 통합 = 본 컨셉과 정합).
- **일정(고정):** 출품 6/8~**6/30 콘솔 첫 빌드 제출** · AU 측정(1차 심사) **7/1~7/26** · 결과 7월 말.
- **상금:** 1등 300만 / 2등 150만×2 / 3등 50만×5.
- **심사:** 1차 = 활성 유저 수(AU) · 최종 = 주제 적합성·UX 종합.
- **규정:** 단순 리워드성 앱 제외, 제3자 IP 침해 불가, 6/8 이전 출시작 불가.

### 성공 지표
- 1차(필수): 7/1~7/26 **AU 극대화**. → 재방문 트리거 + 공유 유입이 제품의 1순위.
- 최종: 주제 적합·완성도·UX.

## 3. 타깃 사용자
주 타깃 20~30대(사주 운세 친화도 높음 → 간판 기능). 매일 아침 루틴 사용자.

## 4. 제품 원칙
1. **"오늘" 단일 축** — 모든 위젯이 오늘로 묶여 "모음 앱의 무덤"(다 얕아짐)을 피한다.
2. **매일 열 이유** — 날씨(즉시 보상)·운세(일진이 매일 바뀜=자연 갱신)·기록 누적(이탈 비용).
3. **개인화 = 이탈 비용** — 홈에 둘 위젯·크기를 직접 조립.
4. **공유 = AU 엔진** — 운세/회고를 텍스트+미니앱 링크로 공유해 신규 유입.
5. **조달 리스크 0** — 외부 크롤링·라이선스 데이터 금지. 사용자 입력 + 자체 계산 + 공공 API만.

## 5. 정보구조 / 화면
- **하단 탭 4개:** 오늘(홈) · 일기 · 돌아보기 · 위젯(편집).
- **온보딩 2단계:** STEP1 위젯 선택(복수) → STEP2 크기 선택. 운세 선택 시 생년월일(+선택 시간/양·음력) 입력. "언제든 바꿀 수 있어요" 안내로 이탈 완화.
- **홈 레이아웃:** 위→아래 **확인(날씨·운세·D-day) → 기록(메모·일기)**. 날씨·운세는 압축 디폴트로 스크롤 최소화. 위젯 on/off·순서는 설정 반영.

## 6. 기능 명세 (풀 라인업 — 6/30 첫 빌드 전부 포함)

| 위젯 | 성격 | 데이터 | 크기 |
|---|---|---|---|
| 날씨 | 확인 | 기상청 공공 API(3시간) | 기본 고정(작게/보통) |
| 사주 운세 | 확인(간판) | 자체 계산(만세력 일진×사주) | 기본 고정(작게/보통) |
| D-day | 확인 | 사용자 입력 | 작게(2열)/보통/크게 |
| 메모 | 기록 | 사용자 입력 | 크기·개수 선택 |
| 일기 | 기록 | 사용자 입력 + 날씨·운세 자동 헤더 | 별도 탭 |

### 6.1 날씨
- 현재 시각 기준 **3시간 타임라인**(가로 스크롤, "지금" 강조, 강수 사전 표시).
- **2지역**(집/회사) 한 카드 좌우 스와이프 + 점 인디케이터(● ○), 높이 고정.
- 부가: 미세먼지 등급·자외선 지수. 압축 디폴트(아이콘·지역·현재/최저최고·뱃지 1줄).

### 6.2 사주 운세 (간판) — 상세는 [ARCHITECTURE.md](./ARCHITECTURE.md) "사주 엔진"
- 입력: 생년월일(+선택 시간), 온보딩 1회 저장.
- 표시: 총운(별점)·재물운·애정운·행운색·행운방향·오늘의 일진·한 줄 조언. 보조: 타로 1장.
- 디폴트: 별점 뱃지+일진+한 줄+화살표(1행) → 탭하면 상세.
- **차별점: 정적 운세표가 아니라 실제 만세력으로 일간×오늘 일진을 계산** → "매일 진짜 바뀌는 내 운세".

### 6.3 D-day
제목+날짜 입력. 크기(작게 2열/보통/크게). 시험·기념일·월급날 카운트다운.

### 6.4 메모
빠른 입력("던지기"). 체크박스(완료 시 취소선). 날짜 연결(그날 일기와 함께 조회 — 선택).

### 6.5 일기
하루 1개. **헤더에 그날 날씨·운세·기분(별점) 자동 삽입**(차별점). 월간 회고의 재료.

### 6.6 돌아보기 (회고 / 공유 = AU 엔진)
- 월간 기분 그래프·일기 모아보기·운세 요약(앱 내 카드).
- **공유:** 텍스트 요약 빌더(예: "오늘 내 운세 ⭐⭐⭐⭐·행운색 초록·재물 방향 南") + `getTossShareLink`(미니앱 링크) + `contactsViral`(친구초대 리워드). *주의: share는 텍스트 전용, 이미지 카드 공유 미지원 → 카드는 앱 내 표시용.*

## 7. 범위 밖 / 후순위 / 미확정
- **제외:** 스포츠 기록 위젯(IP·통일감), 단순 리워드.
- **이번 출품 제외:** 푸시 리마인드(클라 로컬 알림 불가, 서버 필요). 재방문은 운세 일일 갱신+공유로 대체.
- **후순위:** 외부 일기 텍스트 가져오기.
- **확정:** 앱 이름 = **Evry Times**(appName `evrytimes`). 아이콘·리스팅 한 줄 카피는 §9 리스팅에서 확정.

## 8. 마일스톤
- **6/30 전:** 풀 라인업 동작 + .ait 빌드 + 콘솔 제출 + 신청폼.
- **7/1~7/26(AU기간):** 문구뱅크 확장·UX 폴리시·공유 훅 강화(빌드 갱신 가정, 콘솔 확인 필요).

## 9. AU 성장 모델 (★ 1차 심사 직결 — 제품의 1순위)
1차 심사 = 7/1~7/26 활성 유저 수. 기능이 아니라 **AAARR 퍼널**을 제품의 중심에 둔다.
- **Acquisition(유입):** 1순위 채널 = 토스 **테마 지면 큐레이션**. 그래서 *앱 이름·아이콘·한 줄 카피*가 최상위 전환 레버 → 1급 산출물로 관리(미확정→즉시 확정). 2순위 = 사용자 공유 링크(`getTossShareLink`)·친구초대(`contactsViral`).
- **Activation(첫 가치):** 온보딩 이탈 최소화. **빈 홈 금지** — 생년월일 미입력해도 날씨·D-day·메모는 즉시 동작하는 **기본 프리셋**으로 시작, 운세는 "생일 넣고 오늘 운세 보기" 단일 CTA로 유도. 양/음력·시간은 "모름" 허용.
- **Retention(재방문, AU의 핵심):** ① 운세 일진이 **매일 자연 갱신**(열 이유 자동 생성) ② 날씨=아침 즉시 보상 ③ 기록 누적(일기 헤더에 그날 운세·날씨 박제 → 이탈 비용) ④ "어제와 달라진 오늘" 강조 카피.
- **Referral(유입 루프):** 운세 결과·월간 회고를 텍스트+미니앱 링크로 공유, 초대 리워드. 공유 문구에 *결과 일부만 노출+링크로 전체 보기* 호기심 갭 설계.
- **측정:** 토스가 AU를 집계(우리 서버 없음). 가늠용으로 Storage에 `lastOpenDate`·연속출석 streak 기록해 재방문 UX(연속 N일)만 강화(외부 전송 X).

## 10. 컴플라이언스 · 출시 게이트 (★ 통과 못 하면 AU=0)
- 출시 심사를 통과해야 테마 지면 노출 → **심사 통과가 AU의 전제.** 앱인토스 **운영정책/비게임 출시 가이드** 사전 점검 필수.
- 단순 리워드성 앱 제외 규정 → 출석/리워드를 핵심 동력으로 쓰지 않는다(보조만).
- 권한 고지: 위치 권한 사용 사유 명시. 외부 호출 도메인(기상청/에어코리아) 허용 등록.
- 제3자 IP 0 확인: 운세=자체 계산(lunar-javascript MIT), 날씨=공공 API, 타로 텍스트·아이콘 라이선스 확인.

## 11. 비기능 요건
- **성능:** 콜드스타트·만세력 계산은 1회 캐시 후 즉시. 홈 첫 페인트에 네트워크 블로킹 금지(날씨는 캐시 우선 표시 후 갱신).
- **오프라인:** 운세·일기·메모·D-day는 네트워크 0(로컬·계산). 날씨만 온라인 → 마지막 성공 응답 캐시 + 오프라인 폴백 표시.
- **접근성:** 앱인토스 접근성 가이드 준수(명도대비·터치영역·스크린리더 라벨).
- **레이아웃:** Bedrock **safe-area** API로 노치/홈 인디케이터 대응. ~340 폭 기준, 다크모드 토큰 대응(여유 시).

## 12. 개인정보 · 데이터 보존
- 생년월일·일기는 민감 정보 → **전부 로컬 Storage(외부 전송 0)**, 이 사실을 온보딩/설정에 명시(신뢰 = 운세앱 핵심).
- 로컬 한정의 트레이드오프: 앱 삭제/기기 변경 시 소실 → 온보딩에 1줄 고지. (백업/동기화는 7월 이후 Supabase 옵션.)
- 출시 신청에 개인정보 처리방침 요구 여부 콘솔에서 확인.

## 13. 범위 컷라인 (MoSCoW — 16일 현실)
- **Must(6/30):** 온보딩+프리셋 홈, **운세(간판)**, **날씨(2지역·타임라인)**, D-day, 메모, 공유 1종, 빌드·제출.
- **Should(6/30 가능하면):** 일기(자동 헤더), 위젯 편집(순서/크기), 연속출석 streak.
- **Could(7월):** 돌아보기 회고 그래프 확장, 문구뱅크 풀 확장, 타로, 다크모드.
- **Won't(이번):** 서버 동기화, 푸시, 이미지 카드 공유, 외부 일기 가져오기, **결제·광고 등 수익화**(AU 마찰·단순 리워드성 규정 회피 — 수익화는 7/26 이후, [MONETIZATION.md](./MONETIZATION.md) 참조).
- **컷 규칙:** 막히면 운세·날씨 품질을 끝까지 지키고 하위부터 잘라 6/30 제출 → 7월 갱신.

## 14. 사주 정확도 검증 (신뢰 = 운세앱 생명)
만세력 계산은 `lunar-javascript`에 위임하되, **샘플 날짜 10여 개를 공개 만세력(플러스만세력 등)과 대조**해 일진·일주·절기 경계(입춘/월 경계)·자시(23~01시) 날짜 처리·윤달이 일치하는지 출시 전 1회 검증(테스트 픽스처).
