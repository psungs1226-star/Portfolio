API 레퍼런스 / 재시도

retry 정책

요청이 일시적 오류로 실패하면 클라이언트가 재시도합니다. 서버는 재시도 가능 여부를 응답 헤더로 알려주고, 클라이언트는 아래 규칙에 따라 간격을 계산합니다.

재시도는 5xx와 429에만 적용합니다. 4xx는 요청 자체가 잘못된 것이라 재시도해도 같은 결과가 나옵니다.

백오프 계산

기본은 지터를 섞은 지수 백오프입니다. attempt는 0부터 시작합니다.

delay = min(cap, base * 2 ** attempt)
delay = random.uniform(0, delay)   # full jitter

base는 200ms, cap은 20s가 기본값입니다. 지터를 빼면 여러 클라이언트가 같은 시점에 몰려 서버가 다시 넘어집니다.

파라미터기본값설명
base200ms첫 재시도까지의 기준 간격
cap20s간격 상한. 넘어서면 더 늘리지 않습니다
max_attempts5초과하면 마지막 오류를 그대로 올립니다
respect_retry_aftertrue서버가 Retry-After를 주면 계산값 대신 사용

멱등키

쓰기 요청을 재시도하려면 Idempotency-Key 헤더가 필요합니다. 같은 키로 들어온 요청은 최초 결과를 그대로 돌려줍니다.

POST /v1/transfers
Idempotency-Key: 7f3a1c2e-9b40-4d11-8a5f-2c1e6b0d9a33
키를 재사용하면서 본문을 바꾸면 409 Conflict가 반환됩니다. 키는 요청 본문과 함께 저장됩니다.

한도

멱등키는 24시간 보관합니다. 그 이후 같은 키로 요청하면 새 요청으로 처리됩니다.
