## 섹션 레이아웃 패밀리 반복 상한

패턴 14종은 겉모습이 달라도 **구조 시그니처**로 묶으면 6개 패밀리다. 한 페이지에서 같은 패밀리가 연달아 나오면 섹션이 바뀌어도 눈에는 같은 화면이 이어진다 — A/B 프로필 라운드에서 stat-tile·flow-step·timeline-card 세 블록을 연속으로 같은 흰 카드 그리드에 담았다가 "정보위계/스캔성" 12.0 vs 14.0으로 진 실측 근거가 이 절이다.

| 패밀리 | 포함 패턴 | 판정 신호(DOM/CSS) |
|---|---|---|
| 카드 그리드 | Grid · Card · Modular Grid · Masonry | `repeat(N, 1fr)` · `repeat(auto-fit, minmax())` · `columns:` — 같은 크기 셀 3개 이상 |
| 분할 | Split · Sidebar | 트랙 2개(`1.2fr 0.8fr`, `240px 1fr`) |
| 비균등 셀 | Bento · Magazine · 12 Column Grid | 한 그리드 안에서 자식 `grid-column: span N` 값이 서로 다름 |
| 풀폭 흐름 | Editorial · F Pattern · Z Pattern | 열 분할 없이 `max-width` + 중앙/좌측 정렬 텍스트 블록 |
| 표·지표 | Dashboard | `<table>` 또는 KPI 행(`dl` + 수치) |
| 축 시퀀스 | Timeline | 수직 축 + 커넥터(`::before`) 위에 항목 나열 |

상한(마케팅·랜딩·포트폴리오·캠페인 장르. `<header>`/`<footer>`/`<nav>`는 세지 않고 콘텐츠 섹션만 센다):

| 규칙 | 값 |
|---|---|
| 동일 패밀리 연속 | 최대 2섹션 — 연속 3섹션부터 금지 |
| 동일 시그니처(그리드 값까지 같음) 연속 | 최대 3섹션 — 연속 4섹션은 무조건 재구성 |
| 콘텐츠 섹션 6개 이상 | 패밀리 3종 이상 |
| 콘텐츠 섹션 8개 이상 | 패밀리 4종 이상 |
| 한 패밀리 점유율 | 콘텐츠 섹션의 60% 이하 |

장르 구분: **앱·문서 장르에는 적용하지 않는다.** 사이드바+콘텐츠(분할 패밀리)가 페이지 셸이고 표·목록 반복이 그 장르의 올바른 선택이다 — 이 장르의 결함은 반복이 아니라 radius·shadow 값이 제각각인 것이다(§design-system.md).

- 금지: 마케팅 페이지의 콘텐츠 섹션 4개를 전부 `grid-template-columns: repeat(3, 1fr)` 카드 그리드로 배치
- 금지: 섹션 제목만 Bento·Timeline으로 바꾸고 실제 DOM은 전부 `제목 + 균등 카드 그리드 N개`
- 필수: 콘텐츠 섹션 6개 이상이면 패밀리 3종 이상, 동일 패밀리는 연속 2섹션까지

## 동급 항목 비중 차등

같은 종류(프로젝트·사례·제품)라도 성과 크기가 다르면 템플릿을 통일하지 않는다. 프로필 라운드에서 Featured Work 4개를 전부 `이미지+태그+제목+설명+메트릭+링크` 한 템플릿으로 찍어내 636개 테스트를 가진 대형 프로젝트와 단일 기능 프로젝트가 같은 무게로 읽혔고, "프로젝트 표현/설득력" 16.5 vs 18.5로 졌다.

| 항목 수 | 요구 |
|---|---|
| 3개 이하 | 균등 배열 허용 — 비교가 목적일 수 있다 |
| 4개 이상 | 대표 1개를 분리하고 나머지는 압축 형태로 |

- **대표 항목 처리**: 면적 2배 이상(`grid-column: 1 / -1` 전폭 또는 `span 2`)이거나 다른 패밀리(풀폭 split — 좌 이미지/우 서술)로 뺀다. 나머지는 압축 형태(썸네일 제거, 제목+한 줄+수치 3~4행)로 줄인다.
- **차등 폭**: 2배 이상 또는 패밀리 교체. 1.5배 미만 확대는 금지 — 의도가 아니라 실수로 읽힌다.
- **근거는 콘텐츠에서**: 가장 큰 성과 수치 · 가장 최근 · 사용자가 지정한 대표작 셋 중 하나를 고르고, 그 이유를 본문 텍스트에 쓴다(`.pick`·`.flagship`처럼 의미를 담은 클래스로 표시한다). 순서(`:nth-child(1)`)는 근거가 아니다.

`--card-min` 통일 규율과의 관계 — **층위가 달라 충돌하지 않는다**:

| 층위 | 규율 | 대상 |
|---|---|---|
| 토큰 값 | 통일 | `--card-min` 300px · gap · radius — 카드 그리드를 쓰는 모든 곳이 같은 값을 쓴다(열 수가 브레이크포인트마다 어긋나지 않게) |
| 구성 | 차등 | 어떤 항목을 어느 패밀리에 몇 칸으로 놓을지 — 콘텐츠 비중대로 다르게 |

`--card-min`은 "카드 그리드를 쓸 때 그 그리드의 최소 열 폭"을 고정하는 토큰이지 "모든 항목을 같은 카드 템플릿에 넣어라"는 규칙이 아니다.

- 금지: 성과 규모가 10배 차이 나는 프로젝트 6개를 동일 카드 템플릿(이미지+태그+제목+설명+메트릭+링크)으로 균등 배열
- 금지: 대표 항목을 나머지의 1.2배 크기로만 키움
- 금지: 콘텐츠 근거 없이 첫 항목을 전폭으로 확대
- 필수: 동종 항목 4개 이상이면 근거를 본문에 밝힌 대표 1개를 면적 2배 이상 또는 다른 패밀리로 분리하고, 나머지는 압축 형태로 줄인다

## 2px 그리드 규율

모든 간격값은 2px 배수를 쓴다. 홀수값(3/5/7/9px)은 금지한다 — 자간·행간을 제외한 spacing/padding/margin/gap 전부에 적용되는 규칙이다. §design-system.md의 정리 사례("간격 2px 그리드 87% → 100%, 81개 홀수 선언 정리")가 이 규율의 실증 근거다.

## 여백 스케일 — 백지 프로젝트용 6단 토큰

`--fs-micro`~`--fs-disp`(타이포 10토큰)에는 역할 기반 스케일이 있는데 간격에는 없으면, 매번 감으로 8·12·16·20px 근처의 비슷한 값을 골라 결국 모든 여백이 고만고만해진다 — "여백이 약하다"는 인상은 대개 값이 틀려서가 아니라 **인접 티어끼리 차이가 너무 작아서** 생긴다. 아래 6단은 인접 티어 간 최소 1.5배 차이를 규율로 삼는다(§design-system.md "왜 범용 spacing 스케일을 안 만들었는가"는 기존 코드 정리 사례이지 이 규율을 뒤집지 않는다 — 새 프로젝트는 이 표에서 시작한다):

| 토큰 | 값(예시, 문서 밀도) | 용도 |
|---|---|---|
| `--sp-1` | 4px | 아이콘-라벨 사이, 인라인 요소 최소 gap |
| `--sp-2` | 8px | 칩 내부 padding, 태그 사이 gap |
| `--sp-3` | 16px | 카드 내부 padding, 그리드 gap |
| `--sp-4` | 24px | 카드-카드 큰 gap, 컴포넌트 사이 |
| `--sp-5` | 48px | 서브섹션 사이(같은 섹션 안 블록 구분) |
| `--sp-6` | 96px | 섹션과 섹션 사이(페이지 리듬) — `--pad-sec`과 같은 역할 |

값 자체는 장르에 맞게 다시 정해도 되지만(마케팅 랜딩은 `--sp-6`을 140px대로, 밀도 높은 대시보드는 전체를 절반으로) **티어 개수와 "인접 티어 1.5배 이상 차" 규율은 유지**한다. `--sp-4`와 `--sp-5`를 24px/32px처럼 가깝게 잡으면 스케일을 만든 의미가 없다 — 두 섹션 사이인지 두 카드 사이인지 여백만 보고 구별이 안 된다.

## 토큰

> **아래 값은 사례다** — Fieldbook 사이트의 실측값이며, 이식 대상은 "페이지 리듬·radius·카드 최소폭을 토큰으로 고정하고 예외 없이 지킨다"는 규율이다. 값은 장르·스타일에 맞게 재정의한다: 소프트한 스타일이면 radius를 8/12/16px대로, 밀도 높은 앱이면 섹션 리듬을 48–64px대로 새로 정하면 된다. radius 0/2/4px는 Fieldbook의 각진 에디토리얼 톤이라는 하나의 선택일 뿐이다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--r-s` | 0 | 각진 모서리(에디토리얼/각진 톤) |
| `--r-m` | 2px | 기본 라운드 |
| `--r-l` | 4px | 큰 컴포넌트 라운드 |
| `--pad-sec` | 110px | 섹션 상하 패딩(페이지 리듬) |
| `--pad-x` | 28px | 좌우 컨테이너 패딩 |
| `--container` | 1200px | 최대 콘텐츠 폭 |
| `--card-min` | 300px | 카드 그리드 최소 열 폭 — 카드 그리드를 쓰는 모든 곳이 같은 폭에서 접혀 챕터 간 열 수가 어긋나지 않는다(값의 통일이지 템플릿의 통일이 아니다) |

radius 예외: 알약(pill, `999px`)과 원(`50%`)은 칩·점(dot) 전용으로만 허용되는 유일한 예외다.

## 카드 그리드 열 수 정합성

카드 그리드는 아이템 개수와 컬럼 수가 어긋나면 마지막 줄에 카드가 남고 그 옆에 빈 셀(데드스페이스)이 생긴다 — 레이아웃이 깨진 것처럼 보이는 흔한 결함이다.

- **기본값**: `grid-template-columns: repeat(auto-fit, minmax(var(--card-min), 1fr))`을 쓴다. 아이템 수가 컬럼 수를 못 채워도 남는 카드가 그 줄의 폭을 나눠 채우므로 빈 셀이 생기지 않는다.
- **고정 컬럼 수(`repeat(N, 1fr)`)를 쓸 경우**: N은 반드시 아이템 개수의 약수여야 한다(카드 3개 → 3열 또는 1열, 4개 → 4열/2열, 6개 → 3열/2열). 나누어떨어지지 않으면 auto-fit으로 바꾸거나, 마지막 줄 아이템에 `grid-column: 1 / -1` + 중앙 정렬을 적용한다.
- **렌더링 직전 재확인**: 카피는 기획 중 개수가 바뀌기 쉽다(4개 예정이었다가 3개로 줄어드는 식). 그리드 CSS를 짤 때의 예상 개수가 아니라 실제 콘텐츠 개수로 렌더링해 마지막 줄에 빈 셀이 남는지 눈으로 확인한다.

## 2컬럼(텍스트+사이드카드) 분량 균형

긴 본문 텍스트 옆에 짧은 사이드카드(요약표·타임라인 등)를 나란히 두는 2컬럼 레이아웃에서, 두 컬럼의 콘텐츠 분량이 크게 다르면 짧은 쪽이 카드 하나만 덩그러니 있고 그 아래는 텅 비어 "레이아웃이 깨진" 것처럼 보인다 — 카드 그리드 빈 셀과 같은 계열의 결함이다.

- **판단 기준**: 두 컬럼의 텍스트 분량(단어 수 기준) 비율이 2.5배 이상이면 재구성한다.
- **해결 1 — 콘텐츠 재배치**: 스캔 가능한 요소(리스트·표·통계)는 서로 묶고, 서술형 문단은 서술형끼리 묶는다 — 짧은 사이드카드 옆에 있던 불릿 리스트를 사이드카드 쪽으로 옮기면 대개 분량이 맞는다.
- **해결 2 — `position: sticky`**: 정말 사이드카드가 본질적으로 짧다면(예: 연락처 카드) `position: sticky; top: <nav 높이 + 여백>px;`로 고정해 본문을 스크롤해도 따라오게 한다 — 빈 공간이 아니라 의도된 사이드바로 읽힌다.
- `verify.py`가 2컬럼 grid(`grid-template-columns`에 값 2개)의 두 자식 분량 비율을 기계적으로 WARN한다.

## 금지/필수
