# 접근성

접근성은 스타일 위에 얹는 옵션이 아니라 원칙과 같은 층에 있다. 아래 6항목은 실제로 틀렸다가 고친 사례이고 수치도 실측값이다. 출처: UI:UX Fieldbook `A11Y`(6항목, `PRINCIPLES`와 동일 구조).

## A01. 색 대비 (Color Contrast)

WCAG는 본문 텍스트에 **4.5:1**, 18px 이상 큰 텍스트·UI 요소에 **3:1**을 요구한다(AAA는 7:1). 눈대중으로 "잘 보이는데" 싶은 건 믿을 게 못 된다 — 재봐야 안다.

- **금지**: 액센트 원색(`#E04400`)을 9–13px 작은 텍스트에 사용
- **필수**: 더 어두운 단계(`#B33700`)를 작은 텍스트 전용으로 분리. 밝은 단계는 24px 이상·보더·배경 전용. 다크 모드 캡션 `#8A8A93`(5.71:1) 이상
- **원리**: 같은 색의 "역할"을 둘로 나눈다 — 읽는 색과 칠하는 색(§color.md Painting vs Reading Color). 라이트/다크는 각각 따로 측정한다 — 한쪽만 맞추면 반대쪽이 깨진다

## A02. 색만으로 알리지 않기 (Not by Color Alone)

남성의 약 **8%**가 색각 이상이다. 빨강과 초록의 차이로만 상태를 알리면, 그런 사람 눈에는 똑같은 회색 점 두 개다.

- **금지**: 점의 색만 유일한 구분 신호로 사용
- **필수**: 모양(● ▲ ■) + 텍스트 라벨(OK/WARN/DOWN) + 좌측 3px 컬러 바를 함께 사용
- **원리**: 색을 없앤 게 아니라 색에만 의존하지 않게 한다. 흑백으로 복사해도 세 상태가 구별돼야 한다

## A03. 포커스가 보여야 한다 (Visible Focus)

키보드 사용자에게 포커스 링은 마우스 커서와 같다. 지우면 화면 어디에 있는지 알 수 없다. 액센트 배경 위에서 액센트 색 링을 쓰는 것도 지우는 것과 같다.

- **금지**: 포커스 링에 액센트 색 사용
- **필수**: 링은 잉크색(`--ink`), 바깥에 배경색 링을 한 겹 더 두르는 dual-ring. `outline-offset: 2px`
- **원리**: `:focus-visible`만 사용 — 마우스 클릭에는 링이 뜨지 않는다. 대비는 요소 자체가 아니라 요소 "주변"과 비교해 확보한다

## A04. 터치 타깃 크기 (Touch Target)

WCAG 2.2는 최소 **24×24px**를, 모바일 가이드라인은 대체로 **44×44px**를 권한다. 작으면 옆 버튼이 눌린다 — 손이 떨리는 사람에게는 더 크게.

- **금지**: 타깃 간격 2px 미만으로 촘촘히 배치
- **필수**: **44×44px + 간격 8px**. 시각적 크기는 유지하고 padding으로 히트 영역만 키워도 된다
- **원리**: 타깃 사이의 여백이 크기만큼 중요하다 — 빗나가도 아무 일이 없어야 한다. 실수 비용이 큰 버튼은 더 넓게 띄운다

## A05. 이름 없는 컨트롤 (Accessible Name)

아이콘만 있는 버튼은 스크린리더가 그냥 "버튼"이라고만 읽는다. 눈으로 보면 뜻이 통해도 접근성 트리에는 아무것도 남지 않는다.

- **금지**: 아이콘 전용 버튼에 텍스트 라벨·`aria-label` 없이 출시
- **필수**: `aria-label`로 이름 부여, 토글 버튼(즐겨찾기·정렬 등)은 `aria-pressed`로 상태 전달. 장식용 이미지는 `alt=""`
- **원리**: 이름은 "보이는 라벨"과 같은 말로 지어야 음성 제어 사용자가 그대로 부를 수 있다. 상태는 색이 아니라 속성으로 전달한다

## A06. 키보드만으로 끝까지 (Keyboard Path)

마우스 없이 페이지 전체를 쓸 수 있어야 한다. 탭 순서, 건너뛰기, 목록 이동 — 이 셋이 막히면 나머지가 아무리 좋아도 소용없다.

- **금지**: skip-to-content 링크 없이 탭 목록을 본문보다 먼저 배치. 검색 결과를 마우스로만 선택 가능하게 구현
- **필수**: 포커스가 닿을 때만 나타나는 skip-to-content 링크(`main`에 `tabindex="-1"`로 포커스 이동), 검색 결과는 `role="combobox"` + `aria-activedescendant` + 방향키 이동 · Enter 선택 · Esc 닫기
- **원리**: 결과 건수는 `aria-live`로 읽어준다 — 화면을 못 보면 몇 건인지 알 수 없다. `role="listbox"`만 붙이고 `role="option"`이 없으면 없느니만 못하다

## 핵심 수치 요약

- 색상 대비: 본문 **4.5:1**, 큰 텍스트(18px+)·UI 요소 **3:1**, AAA **7:1**
- 터치 타깃: WCAG 2.2 최소 **24×24px**, 권장 **44×44px** + 간격 **8px**
- 색각 이상 남성 약 **8%** — 색만으로 정보 전달 금지
- 포커스: `:focus-visible`만, dual-ring(잉크 링 + 배경색 링)
- 접근 가능한 이름: 아이콘 버튼 `aria-label` 필수, 토글은 `aria-pressed` 병행
- 키보드 경로: skip-to-content + `tabindex="-1"`, 리스트는 `role="combobox"`/`listbox`/`option` + 방향키, 결과 건수 `aria-live`

## 스타일 챕터와의 관계 — 의도적 예외

챕터 화면(제목·본문·버튼·라벨)은 위 기준을 지킨다. 하지만 **§styles.md의 스타일 프리뷰 29개는 일부러 위 기준을 지키지 않는다.** 미니멀리즘의 흐린 회색 본문, 럭셔리의 금색-on-검정, 스큐어모피즘의 가죽 위 각인, 애시드 그래픽의 블렌드 모드는 그 스타일의 정의 자체다. 기준에 맞춰 "고치는" 순간 그건 더 이상 그 스타일이 아니게 되고, 표본이 거짓말을 하게 된다.

**적용 원칙**: 스타일 프리뷰/무드보드 단계에서는 스타일 정의를 있는 그대로 보여준다. 실제 제품에 그 스타일을 적용할 때만 접근성 기준을 재적용한다 — 이 두 층을 혼동해 "미니멀리즘 스타일을 접근성 위반이라고 고치라"는 식으로 지시하지 않는다. 보기 좋은 것과 누구나 읽을 수 있는 것은 저절로 같아지지 않는다.
