# 이미지 시안 (Draft Images)

계획을 코드로 옮기기 전에 **페이지 전체를 이미지 목업 3장으로 먼저 뽑아** 비교하고, 그중 1개를 레퍼런스로 확정해 톤앤매너·레이아웃을 계획에 되먹이는 단계다. `references/styles.md` "Compare Lab"(동일 콘텐츠를 후보 스타일마다 렌더링해 고르는 방법론)의 이미지판이고, 목적도 같다 — **스타일 후보를 설명으로 고르지 않고 보고 고른다.**

이 챕터는 SKILL.md "이미지를 실제로 생성해야 할 때 — 톤앤매너 강제"와 다른 단계다. 그쪽은 완성된 페이지 안에 들어갈 **콘텐츠 이미지**(히어로 비주얼·제품 컷)를 만드는 구현 작업이고, 여기는 **페이지 전체의 시안**을 만들어 방향을 고르는 계획 직후 작업이다.

## 발동 조건

| 조건 | 동작 |
|---|---|
| `장르: 마케팅` | 기본 실행 |
| `장르: 앱` · `장르: 문서` | 사용자가 요청할 때만 |
| `codex` CLI 부재 또는 실행 실패 | **건너뛰고 기존 흐름(계획 → 토큰)으로 진행**, 보고에 생략 사실과 사유를 남긴다 |

파이프라인 부재는 작업 중단 사유가 아니다. 시안 없이도 계획 → 토큰 → 구현 → 게이트는 그대로 성립한다.

## 시안 3개의 변주 축 — 무엇을 다르게 뽑는가

콘텐츠·헤드라인·CTA 문구는 **3장 모두 동일하게 고정한다.** 변주는 아래 한 축에서만 준다.

**색도 고정 대상이다 — 변주 축이 아니다.** 색을 3장에 각자 맡기면 비교에 정보가 늘지 않고 노이즈만 는다(무엇 때문에 그 장이 나아 보이는지 스타일·레이아웃과 뒤섞인다). 게다가 어차피 채택 후 색은 `tokens.py`가 밴드 안으로 보정해 덮어쓰므로, 시안이 보여준 색이 최종 화면의 색이 아니게 된다 — 시안을 보고 고른 근거가 최종물에서 사라지는 것이다.

| 계획 2번의 스타일 후보 수 | 변주 규칙 |
|---|---|
| 2~3개 | 시안 1장당 후보 1개(`draft-a`=후보1, `draft-b`=후보2, `draft-c`=후보3). 후보가 2개면 우세 후보에 레이아웃 변주 1장을 더 준다 |
| 1개(사용자가 스타일 지정) | 같은 스타일의 **레이아웃 변주 3개** — 히어로 패밀리와 섹션 구성을 다르게 짠다(`references/layout.md` 6패밀리: 카드 그리드 · 분할 · 비균등 셀 · 풀폭 흐름 · 표·지표 · 축 시퀀스) |

레이아웃 변주 3개의 예: `a` = 히어로 분할(좌 텍스트/우 이미지) + 카드 그리드 → 축 시퀀스, `b` = 히어로 풀폭 흐름(중앙 대형 헤드라인) + 비균등 셀 벤토 → 표·지표, `c` = 히어로 비균등 셀(헤드라인 셀 + 지표 셀) + 분할 → 풀폭 흐름.

## 색은 시안 **전에** 확정한다 — 두 경로

| 상황 | 순서 | 시안 프롬프트의 색 블록 |
|---|---|---|
| **시드 색조가 이미 있다** — 사용자가 브랜드 색 지정 · 리디자인이라 기존 팔레트가 있음 · 계획 단계에서 색 조합을 확정함 | **`tokens.py`를 시안보다 먼저 돌린다**(SKILL.md 진입 순서 5 → 4 순서로) | 확정된 **hex를 그대로** 박는다: `--acc` · `--bg` · `--surface` · `--ink`. 3장 전부 같은 값 |
| **시드가 전혀 없다** — 색조를 시안으로 탐색하겠다고 계획에 적은 경우에만 | 기존 순서(시안 → 토큰) | 색조 이름 + 톤 밴드만(hex 없음). 이때도 3장은 **같은** 색 지시를 받는다 |

기본값은 위쪽이다. 아래쪽은 "색을 아직 못 정했다"가 계획에 명시된 예외 경로다 — 정해놓고 안 넘기는 것은 그냥 누락이다.

**왜 hex까지 박는가**: SKILL.md는 콘텐츠 이미지에 대해 이미 "이미지 생성기가 스스로 배색을 고르게 두지 않는다 — `--acc`/`--bg`/`--surface`를 그대로 팔레트 제약으로 넘긴다"를 강제하고 있다. 페이지 전체 시안이라고 기준이 달라질 이유가 없다. 이미지 모델이 hex를 정확히 재현하지는 못하지만, 색조·명도·채도 방향은 확실히 따라온다 — "따뜻한 오렌지"보다 `#D0460D`가 훨씬 좁은 지시다.

## 프롬프트 구성 — 시안 1장당 6블록

시안 프롬프트는 SKILL.md의 콘텐츠 이미지 4항목을 페이지 단위로 확장한 것이다. 아래 6블록을 **전부** 넣는다. 하나라도 빠지면 범용 SaaS 목업이 돌아온다.

1. **형식** — 데스크톱 1440px 기준 랜딩 페이지 풀페이지 목업, 히어로 + 섹션 3~5개가 세로로 이어진 한 장. 세로 비율을 숫자로 지정한다(`가로:세로 = 3:5`)
2. **스타일** — 스타일/프리셋명 + DNA 극단 축 + **결정적 동작**. 프리셋이면 `references/styles/contemporary.md`의 결정적 동작을 문장 그대로 옮긴다(예: `bento-showcase` → "셀 크기 3종 이상·최대 셀이 최소 셀의 4배·셀 배경 3종")
3. **팔레트** — 확정된 토큰 hex를 그대로 넣는다(`--acc`/`--bg`/`--surface`/`--ink`) + TPO 톤(절제/중립/임팩트) + "액센트 1갈래" 제약. 팔레트가 아직 없는 예외 경로에서만 hex 대신 색조 이름 + 저채도/고채도 방향을 쓴다(위 "색은 시안 전에 확정한다")
4. **콘텐츠** — 계획 1번의 콘텐츠 우선순위를 **위→아래 순서 그대로** 나열한다. 실제 브랜드명·헤드라인 카피·섹션별 실제 항목까지. 다른 프로젝트에 그대로 옮기면 말이 안 되는 수준이어야 한다
5. **금지 목록** — AI-purple 그라데이션, 추상 지오메트릭/전구/로켓/3D blob, 균일한 흰 카드 3열 나열, 영문 lorem 텍스트 벽
6. **한글 한계 전제** — "한글 텍스트는 근사 렌더링이어도 무방하다. 텍스트 판독성은 평가 대상이 아니다"를 프롬프트에 명시한다. 폭 864px로 축소돼 나오므로 본문 글자는 원래 안 읽힌다

프롬프트 파일 골격(`drafts/prompt-a.txt`):

```
이미지를 1장 생성하라.

형식: 데스크톱 1440px 기준 랜딩 페이지 풀페이지 목업. 세로로 히어로 + 섹션 <N>개가
이어진 세로로 긴 한 장(가로:세로 = 3:5).

스타일: <스타일/프리셋명>. DNA 극단 축 = <축과 수치>. 결정적 동작 = <2~3개>.

팔레트(이 색만 쓴다): 액센트 <--acc hex> 1갈래만 · 배경 <--bg hex> ·
카드/표면 <--surface hex> · 텍스트 <--ink hex>. 톤은 <절제|중립|임팩트>.
이 팔레트 밖의 색을 새로 만들지 마라(특히 보라·틸을 액센트로 추가하지 마라).
  ※ 팔레트 미확정 예외 경로일 때만 이 줄을 다음으로 대체:
    톤 밴드: <절제|중립|임팩트>. 액센트는 <색조명> 1갈래만, 배경은 <배경 톤>,
    텍스트는 <텍스트 톤>. <고채도|저채도> 금지.

콘텐츠(이 순서 그대로):
- 브랜드명 '<실제 브랜드명>' — <한 줄 정체>
- 히어로 헤드라인 '<실제 카피>'
- 섹션1: <실제 항목>
- 섹션2: <실제 항목>
- 섹션3: <실제 항목>

금지: AI-purple 그라데이션, 추상 지오메트릭/전구/로켓/3D blob,
균일한 흰 카드 3열 나열, 영문 lorem 텍스트 벽.

한글 텍스트는 근사 렌더링이어도 무방하다. 텍스트 판독성은 평가 대상이 아니다.

생성한 이미지 파일을 현재 작업 디렉토리의 drafts/draft-a.png 로 복사하라
(mkdir -p drafts 후 cp). 복사 후 ls -la drafts/ 로 확인하고 최종 메시지에 저장 경로를 적어라.
```

## 실행 — 검증된 커맨드

`codex` CLI 0.147.0에서 실측 검증한 형태다. 시안 3장 = 호출 3회, 프롬프트 파일만 바꾼다.

**3회를 순차로 돌리지 않는다 — 동시에 띄운다.** 호출당 실측 94초라 순차면 5분이 그냥 날아가는데, 세 호출은 서로 완전히 독립이다(입력 프롬프트도 출력 파일도 다르다). 백그라운드로 셋을 함께 띄우고 `wait`로 받는다 — 같은 3장이 ~100초에 나온다:

```
cd <작업 디렉토리 절대경로>
for v in a b c; do
  codex exec --skip-git-repo-check --sandbox workspace-write \
    -C "$PWD" - < "drafts/prompt-$v.txt" > "drafts/log-$v.txt" 2>&1 &
done
wait
ls -la drafts/
```

한 장씩 확인하며 돌려야 할 때(프롬프트를 고쳐가며 1장만 재생성 등)의 단건 형태:

```
codex exec --skip-git-repo-check --sandbox workspace-write \
  -C <작업 디렉토리 절대경로> - < drafts/prompt-a.txt > drafts/log-a.txt 2>&1
```

- `--skip-git-repo-check` **필수** — 없으면 `Not inside a trusted directory` 한 줄만 남기고 아무것도 안 한다(작업 디렉토리가 git 저장소가 아닐 때)
- `--sandbox workspace-write` **필수** — `-C`로 지정한 디렉토리에 `cp`할 권한이 이것으로 열린다. 없으면 이미지가 `~/.codex/generated_images/`에만 남는다
- 프롬프트는 `-` + stdin 리다이렉트로 넘긴다. 위치 인자로 넘겨도 되지만 긴 한글 프롬프트는 셸 이스케이프에서 깨진다
- 산출 경로는 `<작업 디렉토리>/drafts/draft-{a,b,c}.png`로 통일한다
- 타임아웃은 **호출당 300초 이상**을 잡는다 — 실측 94초, 이미지 1장 기준
- 모델 고정이 필요하면 `-m <MODEL>`(기본 `gpt-5.6-terra`), 참조 이미지를 붙이려면 `-i <FILE>`

**exit code를 성공 판정에 쓰지 않는다.** 위 실패(trusted directory)에서도 exit 0이 나왔다. 판정은 파일 존재로 한다:

```
test -s drafts/draft-a.png || echo "FAILED: draft-a"
```

파일이 없으면 codex가 생성은 했는데 복사만 실패한 경우일 수 있다. 최신 세션 폴더에서 수확한다:

```
cp "$(ls -t ~/.codex/generated_images/*/*.png | head -1)" drafts/draft-a.png
```

**이 수확은 동시 실행 중에는 쓰지 않는다** — `ls -t | head -1`이 어느 호출의 이미지인지 구별하지 못해 다른 시안을 집어온다. 동시 실행에서 빠진 장이 있으면 **그 한 장만 단건 형태로 다시 돌리고**, 그때 수확한다.

실측 산출물: 864×1821px PNG(약 1.4MB). 요청한 3:5보다 세로로 길게 나온다 — 비율은 근사치이고 폭은 1440px가 되지 않는다.

- 금지: 3회 호출의 콘텐츠 블록을 조금씩 다르게 쓰기 — 비교가 성립하지 않는다. 변주는 스타일 블록 또는 레이아웃 지시에만 준다
- 필수: 3회 호출 모두 같은 프롬프트 파일에서 복사해 만들고, 바꾼 줄이 어디인지 스스로 셀 수 있는 상태로 둔다

## 평가 — 5축 채점

시안 3장을 Read로 **나란히** 읽고 아래 축으로 채점한다. 시안당 근거 2~3줄을 기록한다.

| 축 | 판정 기준 |
|---|---|
| 계획 적합성 | 계획 1번의 콘텐츠 우선순위가 화면 비중(면적·위치)에 반영됐는가. 선언한 톤 밴드로 보이는가. **팔레트를 박아 넘겼으면 그 팔레트로 보이는가** — 액센트가 다른 색조로 바뀌었거나 팔레트 밖 색이 새로 들어왔으면 그 장은 지시를 안 따른 것이다 |
| 스타일 커밋 가시성 | **스타일 이름을 가려도 그 스타일/프리셋으로 읽히는가.** radius·보더·그림자·색 강도 중 최소 1축이 극단으로 보여야 한다 |
| 레이아웃 다양성 | 섹션들이 `references/layout.md` 6패밀리 기준 몇 종으로 읽히는가. 동일 패밀리 연속 3섹션은 탈락(반복 상한 준용) |
| 슬롭 시그니처 | AI-purple 그라데이션·스톡 무드·균일 카드 반복이 보이는가. **하나라도 강하면 그 시안 탈락** |
| 텍스트 | **감점하지 않는다.** 한글 깨짐·잘림은 이미지 모델의 한계이지 시안의 결함이 아니다 |

- 사용자가 세션에 있으면(대화형) 3장을 보여주고 선택을 요청한다
- 자율 실행이면 위 채점으로 자체 선정하고 **채택 근거와 탈락 사유를 보고에 남긴다**
- 3장 모두 슬롭 탈락이면 프롬프트를 고쳐 **1회만** 재생성한다. 무한 재시도 금지 — 2회차도 전멸이면 시안 단계를 생략하고 계획대로 진행한다

## 레퍼런스 추출 — 톤앤매너·레이아웃

선택한 시안이 기존 파이프라인에 합류하는 지점이다. 시안에서 **뽑는 것**과 **뽑지 않는 것**을 구분한다.

- **색**: 팔레트를 미리 박았으면 **여기서 뽑을 것이 없다** — 토큰이 이미 확정이고 시안은 그걸 따라 그린 것이다. 시안 픽셀이 토큰과 달라 보여도(이미지 모델이 hex를 정확히 못 맞춘다) 토큰을 시안 쪽으로 옮기지 않는다. 팔레트 미확정 예외 경로였을 때만 주조·액센트의 **색조만** 샘플링해 `python3 scripts/tokens.py '<시드 hex>' <톤>`의 시드로 넘긴다. 어느 경우든 시안 색이 톤 밴드나 대비 기준을 어기면 **시안이 아니라 게이트가 이긴다** — tokens.py가 보정해 내놓은 값을 쓰고, 시안 픽셀값을 토큰에 직접 적지 않는다
- **레이아웃**: 시안의 섹션 구조를 위→아래로 `references/layout.md` 14종/6패밀리에 매핑해 계획 3번(레이아웃 칸)을 갱신한다. 매핑 결과가 반복 상한(동일 패밀리 연속 2섹션, 섹션 6개 이상이면 3종 이상)을 어기면 시안을 그대로 따르지 않고 **어긋난 섹션만 다른 패밀리로 교체**한다
- **스타일**: 시안이 실제로 보여준 커밋 축(radius·보더·그림자·색 강도)을 기록하고 계획 2번의 결정적 동작 목록과 대조한다. **시안에 안 보이는 결정적 동작은 구현에서 추가한다** — 시안은 근사치이고, 프리셋의 결정적 동작을 빠뜨리면 금지 스타일과 동일 판정이다(`references/styles/contemporary.md`)

### 시안의 지위 3원칙

1. 시안은 **참고물**이지 픽셀 복제 대상이 아니다
2. 스킬 게이트(대비·크로마 밴드·슬롭 시그니처·모션 규칙)와 충돌하면 **항상 게이트가 이긴다**
3. 시안 PNG를 최종 페이지에 **콘텐츠 이미지로 삽입하지 않는다** — 시안은 산출물의 자산이 아니다

## 금지/필수

- 금지: 시안 3장을 같은 스타일·같은 레이아웃으로 뽑기 — 1장을 3번 생성한 것이다
- 금지: 시안마다 헤드라인·CTA 문구를 바꿔서 생성
- 금지: 시안의 보라 그라데이션을 톤 밴드 위반인 채로 토큰에 이식
- 금지: 시안에서 뽑은 hex를 `tokens.py`를 건너뛰고 `--acc`에 직접 지정
- 금지: 팔레트가 이미 정해져 있는데 시안 프롬프트에 hex를 안 넣고 "따뜻한 오렌지" 같은 색조 이름으로 대신하기 — 정해놓고 안 넘기는 것은 누락이다
- 금지: 3장에 서로 다른 팔레트를 주고 색까지 비교하려는 것 — 변주 축은 스타일 또는 레이아웃 하나뿐이다
- 금지: 시안의 섹션 구조를 그대로 옮겨 동일 패밀리를 연속 3섹션 이상 배치
- 금지: 한글이 깨졌다는 이유로 시안 탈락 처리
- 금지: 시안 3장이 전부 슬롭일 때 프롬프트를 조금씩 고치며 3회 이상 재생성
- 금지: 선택한 시안 PNG를 페이지의 히어로 이미지로 삽입
- 필수: 3장의 콘텐츠 블록(브랜드명·헤드라인·CTA·섹션 항목)을 동일하게 고정한다
- 필수: 프롬프트 6블록(형식·스타일·**팔레트**·콘텐츠·금지 목록·한글 전제)을 전부 넣는다
- 필수: 시드 색조가 이미 있으면 `tokens.py`를 시안보다 **먼저** 돌리고 나온 hex를 3장 전부에 동일하게 박는다
- 필수: 성공 판정을 exit code가 아니라 `test -s drafts/draft-<x>.png`로 한다
- 필수: 선택 시안의 채택 근거와 나머지 2장의 탈락 사유를 보고와 `/* plan */`에 남긴다
- 필수: codex 실행 실패 시 시안 단계를 생략하고 계획 → 토큰으로 진행하며 생략 사실을 보고한다
