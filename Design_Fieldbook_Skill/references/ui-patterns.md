# UI 패턴

내비게이션·콘텐츠·피드백·입력 4카테고리 18종. 각 패턴은 언제 쓰는가/피해야 할 때/흔한 실수를 함께 갖는다. 출처: UI:UX Fieldbook `UI_PATTERNS` + `PATTERN_GUIDE`.

## Navigation (5)

| 패턴 | 설명 | 언제 쓰는가 | 피해야 할 때 | 흔한 실수 |
|---|---|---|---|---|
| Navbar | 로고·메뉴·CTA가 한 줄, 모바일은 햄버거로 수축 | 사이트 전체의 탐색 골격이 필요할 때 | 기능 10개 이상의 깊은 서비스(진입 장벽이 됨) | 모바일에서 메뉴를 전부 한 줄에 쏟아내는 것 |
| Sidebar | 항상 보이는 좌측 내비게이션, 좁은 화면에선 접힘 | 탐색이 많고 자주 오가는 앱·대시보드 | 콘텐츠 중심의 마케팅 페이지 | 화면이 좁은데도 접지 않고 화면을 막는 것 |
| Tab | 섹션을 탭으로 나눠 상태를 유지하며 전환 | 동일 계층의 콘텐츠를 빠르게 전환할 때 | 순서가 강제되는 절차(결제·가입) | 탭 수를 지나치게 늘려 각 탭이 비어 보이게 하는 것 |
| Breadcrumb | 현재 위치가 홈에서 몇 단계인지 경로로 표시 | 깊이가 깊은 페이지에서 현재 위치를 보여줄 때 | 한 단계짜리 얕은 구조 | 이동할 수 없는 텍스트로 장식만 하는 것 |
| Drawer | 화면 밖에서 슬라이드로 들어오는 메뉴, 배경을 어둡게 해 집중 유도 | 모바일에서 많은 탐색을 접어둘 때 | 핵심 탐색을 항상 감추면 발견성이 떨어짐 | 드로어 안에서 또 드로어를 여는 중첩 |

## Content (5)

| 패턴 | 설명 | 언제 쓰는가 | 피해야 할 때 | 흔한 실수 |
|---|---|---|---|---|
| Card | 이미지·제목·설명·행동이 하나의 카드로 묶임 | 독립된 정보 단위(상품·글·기능)를 나열할 때 | 행 단위로 비교해야 하는 데이터(표가 낫다) | 카드 하나에 행동 버튼을 여러 개 넣는 것 |
| Table | 행을 클릭하면 정렬, 정량 데이터의 표준 | 정렬·비교·수치가 중심일 때 | 이미지·스토리 위주의 콘텐츠 | 정렬 가능한 헤더임을 전혀 알려주지 않는 것 |
| Timeline | 마일스톤과 진행 상태를 세로로 배치 | 시간 순서나 진행 상황을 보여줄 때 | 순서가 무의미한 단순 목록 | 날짜만 나열하고 맥락을 생략하는 것 |
| Kanban | 카드를 클릭하면 다음 단계로 이동, 진행 흐름을 한눈에 | 작업 상태를 단계로 나눠 관리할 때 | 단계가 두 개뿐인 단순 흐름 | 카드 이동이 불가능한 정적인 보드 |
| Carousel | 화살표 또는 자동 전환으로 슬라이드를 넘김 | 시각 콘텐츠를 순환 전시할 때 | 중요 정보를 슬라이드에만 숨길 때 | 자동 재생에 핵심 콘텐츠를 맡기는 것 |

## Feedback (4)

| 패턴 | 설명 | 언제 쓰는가 | 피해야 할 때 | 흔한 실수 |
|---|---|---|---|---|
| Modal | 배경을 잠그고 중심에 대화상자, 결과를 확인해야 넘어감 | 사용자의 중요한 결정·확인이 필요할 때 | 긴 콘텐츠나 복잡한 폼(별도 페이지가 낫다) | 모달 안에 또 모달을 여는 중첩 |
| Toast | 하단에서 잠깐 떴다 사라지는 알림, 행동을 방해하지 않음 | 짧고 가벼운 상태 피드백(저장·삭제) | 되돌릴 수 없는 중대한 결과(모달로) | 여러 개를 동시에 쌓아 올리는 것 |
| Tooltip | 마우스를 올리면 짧은 설명이 나타남 | 요소 옆에 붙이는 짧은 보충 설명 | 필수 정보를 툴팁에만 넣는 것 — 정보를 화면 밖으로 밀어낸다 | 호버가 없는 모바일에서만 동작하게 만드는 것 |
| Alert | 유형(정보·성공·경고·오류)에 따라 색과 아이콘이 정해짐 | 상태를 즉시 알릴 때 | 사소한 변화마다 전체 배너를 띄우는 것 | 모든 알림을 같은 색·레벨로 처리하는 것 |

## Input (4)

| 패턴 | 설명 | 언제 쓰는가 | 피해야 할 때 | 흔한 실수 |
|---|---|---|---|---|
| Search | 입력하면 아래 결과가 실시간 필터링 | 목록이 길어 필터링이 필요할 때 | 아이템이 10개 미만일 때 | 결과가 없을 때의 안내(빈 상태)가 없는 것 |
| Form | 필수 입력을 검증하고 오류·성공 메시지 표시, 라벨은 항상 필드 위에 | 구조화된 데이터 입력이 필요할 때 | 한 줄 답변에 폼 전체를 쓰는 것 | 라벨 없이 placeholder에만 의존하는 것 |
| Date Picker | 달력에서 날짜를 고름, 오늘 날짜 강조 | 달력 기반 날짜 선택이 자연스러울 때 | 항상 같은 날짜만 고를 때(선택 비용 커짐) | 키보드 입력과 스크린리더를 배제하는 것 |
| Stepper | 수량을 조절하고 진행 단계를 시각화 | 수량 조절 + 진행 단계를 함께 보여줄 때 | 단계가 한두 개뿐인 흐름 | 단계 표시가 실제 진행 상태와 어긋나는 것 |

## 금지/필수

- 금지: 되돌릴 수 없는 삭제 확인을 Toast로 처리
- 금지: 저장 성공/필드 오류/삭제 확인 등 모든 상태 피드백에 획일적으로 Modal 사용
- 필수: 가볍고 되돌릴 수 있는 피드백은 Toast, 중요하고 되돌릴 수 없는 결정은 Modal — 무게에 맞는 패턴 선택(§motion.md 2.1 Productive/Expressive와 같은 판단축)
- 금지: 카드 하나에 배지 칩 + 좌측 컬러 보더 + 인용 박스 + 스탯 타일을 동시에 쌓는 것 — 스타일을 뭘 고르든 반복되는 범용 AI 카드 조합이라 스타일 이름을 가려도 구별이 안 된다
- 필수: 카드당 장식 장치(컬러 보더·그림자·배지·인용 박스·스탯 타일) 최대 2개. 나머지 정체성은 선택한 스타일이 실제로 정의한 컴포넌트로 표현한다(Material이면 elevation 단계·FAB, Material You면 tonal container — `references/styles/modern.md` 관찰 포인트 참고)
- 필수: 반복되는 리스트/카드 항목(3개 이상)에서 가장 중요한 지표 최소 1개는 font-weight·배경 칩·크기 중 하나로 나머지와 구분한다 — 전 항목이 완전히 동일한 배경색으로만 처리되면 강조가 아니라 착색이다(`references/color.md` "콘텐츠 내부 강조")
- 금지: 표 헤더(`<th>`) 폰트를 본문 셀(`<td>`)보다 작은 caption 크기로 잡고 좌측 정렬
- 필수: 표 헤더는 본문 셀 대비 타입 스케일 최소 한 단계 위(`references/typography.md` 8토큰 기준) + `font-weight:700` + `text-align:center`. 헤더가 본문보다 작고 왼쪽 정렬이면 "이게 헤더다"라는 신호가 안 읽힌다 — 같은 실수가 서로 다른 두 산출물에서 독립적으로 재현됐다
