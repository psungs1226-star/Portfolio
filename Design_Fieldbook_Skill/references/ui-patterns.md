# UI 패턴

내비게이션·콘텐츠·피드백·입력 4카테고리 18종. 각 패턴은 언제 쓰는가/피해야 할 때/흔한 실수를 함께 갖는다. 출처: UI:UX Fieldbook `UI_PATTERNS` + `PATTERN_GUIDE`.

|---|---|---|---|---|
| Navbar | 로고·메뉴·CTA가 한 줄, 모바일은 햄버거로 수축 | 사이트 전체의 탐색 골격이 필요할 때 | 기능 10개 이상의 깊은 서비스(진입 장벽이 됨) | 모바일에서 메뉴를 전부 한 줄에 쏟아내는 것 |

| Breadcrumb | 현재 위치가 홈에서 몇 단계인지 경로로 표시 | 깊이가 깊은 페이지에서 현재 위치를 보여줄 때 | 한 단계짜리 얕은 구조 | 이동할 수 없는 텍스트로 장식만 하는 것 |
| Drawer | 화면 밖에서 슬라이드로 들어오는 메뉴, 배경을 어둡게 해 집중 유도 | 모바일에서 많은 탐색을 접어둘 때 | 핵심 탐색을 항상 감추면 발견성이 떨어짐 | 드로어 안에서 또 드로어를 여는 중첩 |

## 표(Table) 강제 규칙

표에서만 같은 결함 네 가지가 산출물마다 독립적으로 재현됐다. 아래는 권장이 아니라 **강제**이며, 네 항목 전부 `scripts/verify.py`(정적)와 `scripts/render_audit.py`(렌더)가 기계로 잡는다.

- **헤더 구별** — 필수: 표 헤더(`<th>`)는 본문 셀(`<td>`) 대비 타입 스케일 최소 한 단계 위(`references/typography.md` 8토큰 기준) + `font-weight:700` + `text-align:center`. 금지: 헤더를 본문보다 작은 caption 크기로 잡고 좌측 정렬 — "이게 헤더다"라는 신호가 안 읽힌다
- **첫 열 가운데 정렬** — 필수: 첫 열은 `th`·`td` 둘 다 `text-align:center`(`th:first-child, td:first-child { text-align: center }`를 명시적으로 선언한다). 헤더만 가운데고 값은 왼쪽이면 열 축이 어긋나 보인다. 첫 열 텍스트가 두 줄로 접혀도 center를 유지한다 — 정렬을 푸는 게 아니라 열 폭(`width`/`min-width`)을 늘리거나 라벨을 줄인다. 셋째 열부터의 정렬은 자유(수치 열은 `text-align:right` + `font-variant-numeric:tabular-nums`)
- **행 구분선은 전 행에 필수** — 필수: 데이터 행이 3개 이상이면 **모든 행 경계**에 실제로 보이는 선을 긋는다(`tbody td { border-bottom: 1px solid var(--line) }`). 선 색은 그 행 배경 대비 **3:1 또는 RGB 델타 18** 이상(§SKILL.md "구분선은 대비식만으로 판정하지 않는다"). 헤더 아래 경계는 본문 행선보다 **굵거나(2px) 진하게** 해서 헤더 블록을 닫는다. 금지: 헤더 아래에만 선 하나 긋고 데이터 행 사이는 비워두는 표 · `border:none`으로 선을 전부 지운 표 — "구분선을 넣으라"는 지시에 헤더 밑줄 하나로 답한 산출물이 반복해서 나왔다. 행 간격(`padding`)은 구분선의 대체재가 아니다
- **행 틴트는 정확히 한 행** — 필수: 강조 행·그룹 구분 행의 배경 틴트는 **그 한 행에만** 적용한다(틴트는 `tr`이 아니라 그 행의 `th`/`td`에 걸어 스코프를 눈에 보이게 한다). 금지: ① 인접한 두 행이 같은 틴트를 갖는 것 — 특히 **헤더 배경색과 첫 데이터 행 배경색이 같은 경우**(두 행이 한 덩어리로 읽혀 헤더 경계와 구분 행 신호가 동시에 사라진다) ② 틴트를 형제 결합자(`tr.group + tr`, `.group ~ tr`)로 확장하는 것 ③ 구분 행 틴트와 `:nth-child(odd/even)` 줄무늬를 한 표에서 같이 쓰는 것 — 줄무늬가 구분 행과 같은 계열이면 어느 행이 구분 행인지 판별 불가능해진다. 강조를 두 행 이상에 걸쳐야 한다면 그건 틴트가 아니라 **그룹**이므로 `<tbody>`를 나누고 그룹 사이에 굵은 rule을 넣는다

## 금지/필수

- 금지: 되돌릴 수 없는 삭제 확인을 Toast로 처리
- 금지: 저장 성공/필드 오류/삭제 확인 등 모든 상태 피드백에 획일적으로 Modal 사용
- 필수: 가볍고 되돌릴 수 있는 피드백은 Toast, 중요하고 되돌릴 수 없는 결정은 Modal — 무게에 맞는 패턴 선택(§motion.md 2.1 Productive/Expressive와 같은 판단축)
- 금지: 카드 하나에 배지 칩 + 좌측 컬러 보더 + 인용 박스 + 스탯 타일을 동시에 쌓는 것 — 스타일을 뭘 고르든 반복되는 범용 AI 카드 조합이라 스타일 이름을 가려도 구별이 안 된다
- 필수: 카드당 장식 장치(컬러 보더·그림자·배지·인용 박스·스탯 타일) 최대 2개. 나머지 정체성은 선택한 스타일이 실제로 정의한 컴포넌트로 표현한다(Material이면 elevation 단계·FAB, Material You면 tonal container — `references/styles/modern.md` 관찰 포인트 참고)
- 필수: 반복되는 리스트/카드 항목(3개 이상)에서 가장 중요한 지표 최소 1개는 font-weight·배경 칩·크기 중 하나로 나머지와 구분한다 — 전 항목이 완전히 동일한 배경색으로만 처리되면 강조가 아니라 착색이다(`references/color.md` "콘텐츠 내부 강조")
