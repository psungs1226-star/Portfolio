## 4. 두 시안의 해석과 수정 지시

### A — Paper Editorial / reference-A-paper.png

- 채택할 것: 따뜻한 종이색 바탕, 초대형 굵은 고딕 이름, 좌우 비대칭 히어로, 숲색 72%, 얇은 구분선, 평면 문서.
- 차별적 구성: 히어로 이름 5열, 소개 5열, 나머지 여백. 아래 관찰 장면은 제목 7열·지표 5열. 계속 같은 좌우 비율을 반복하지 않는다.
- 고칠 것: 이미지 상단 오른쪽에 추가된 자기소개 문구는 삭제. 사업모델의 원형 아이콘 4개와 카드형 매출 상자는 가는 연결선과 타이포 중심으로 단순화. 문서 3장 축소 나열을 실제 1페이저 한 장의 큰 뷰로 바꾼다.
- 배경의 생성된 종이 얼룩·조명은 CSS로 복제하지 않는다. 평평한 단색을 사용한다.

### B — Ink Dossier / reference-B-ink.png

- 채택할 것: 먹색 바탕, 큰 한글 명조 이름, 작은 좌측 인덱스, 어두운 바탕 위 밝은 실제 문서, 제품 섹션에서 백색으로 전환.
- 차별적 구성: 이름과 소개의 8:4 히어로. 관찰 장면은 지표 5열·문서 7열. 실행 장면은 제목 4열·문서 8열. 밝고 어두운 큰 면의 교체로 장면 전환을 만든다.
- 명조는 이름과 주요 제목에만 쓴다. 본문·버튼·표는 고딕. 지나치게 가늘거나 붓글씨 느낌의 폰트는 피한다.
- 고칠 것: 이미지의 문서 부채꼴 겹침은 실제 구현에서 최대 2장, 0~2도 회전 이하. 핵심 문서는 정면으로 펴서 읽을 수 있게 한다. 이미지에 생성된 기업명·날짜·도표는 전부 원본으로 교체. 제품 화면 하단 잘림을 없애고 실제 비율을 보존한다.
- 이미지의 녹색 광택·비네팅·배경 질감은 재현하지 않는다. 단색 잉크 배경이 기준이다.

공통: 이미지 전체를 페이지 배경으로 사용하거나 이미지의 글자를 잘라 HTML처럼 사용하는 행위 금지. 모든 카피는 실제 텍스트, 도표는 SVG/HTML, 인터랙션은 실제 DOM으로 구현한다. 생성 이미지의 문서·앱 화면은 증거 자료가 아니다.

### 6.1 사업모델 가로 이동의 정확한 구조

`section > heading + viewport > track > stage×4` 구조. pin은 section 또는 고정 전용 wrapper에, transform은 내부 track에 적용한다. 같은 요소에 pin과 x 이동을 함께 적용하지 않는다.

- viewport는 overflow hidden. track은 flex, stage는 데스크톱에서 약 340~420px. 첫 화면에 2.5~3개 단계가 보여 다음 단계 존재를 암시한다.
- distance = max(0, track.scrollWidth - viewport.clientWidth).
- distance가 0이면 horizontal tween과 pin을 생성하지 않는다.
- x = -distance. ease none. end는 distance 기반으로 결정하되 전체 추가 스크롤이 약 1.5 화면을 넘지 않도록 실제 panel 폭을 조정한다.
- 문구는 단계 진입 전부터 읽을 수 있다. opacity 0으로 정보 자체를 숨기지 않고 활성 단계의 색·밑줄만 변화시킨다.
- 진행 UI는 '01—04'와 짧은 선 정도. 강제 snap은 기본 OFF.
- 하위 단계 트리거에 containerAnimation을 사용할 경우 가로 tween을 연결하고 하위 pin/snap을 추가하지 않는다.
- 선은 transform scaleX 또는 SVG stroke로 표현하되 복잡한 SVG 필터는 사용하지 않는다.
- '우선 컨택권'은 기업 컨택, '성사 수수료'는 채용 성사에 연결해 의미가 있는 강조만 한다.

### 6.2 실행 자료의 3상태

1. 전체 1페이저: 형태와 제목을 충분히 보여준다.
2. 실제 문서의 핵심 가치/영업 제안 영역: 동일 이미지 위 얇은 테두리 또는 배경 딤으로 강조. 핵심 내용은 옆의 HTML 텍스트로도 제공.
3. 준비된 타겟·계획과 검증 기준: 원본에서 확인한 내용만 노출. 실제 문서에 해당 영역이 없다면 문서를 왜곡하지 말고 옆 설명을 바꾼다.

타임라인에 `overview`, `offer`, `validation` 라벨을 둔다. 각 장면에서 전환은 약 20~25%, 읽는 구간은 나머지를 사용한다. scale 최대 1.025, translate 최대 24px. 중요한 문서 영역을 프레임 밖으로 잘라 확대하지 않는다. PDF 열기 링크는 고정 구간 내내 노출한다.

### 6.3 반응형·모션 감소

- 최소 `min-width: 1100px` AND `min-height: 720px` AND `prefers-reduced-motion: no-preference`일 때만 pin 2개를 활성화하는 출발안을 사용.
- 태블릿·모바일은 4단계를 세로 목록 또는 모두 보이는 2×2 구성으로 표시. 가로 스와이프를 해야 정보를 얻는 구조 금지.
- 모바일 실행 장면은 전체 문서 1장 + 아래 요약 + PDF 링크. 숨겨진 3상태를 만들지 않는다.
- reduced-motion은 pin/scrub/parallax/자동 스크롤 전부 해제하고 모든 최종 내용을 DOM 흐름에 노출.
- gsap.matchMedia로 분기하고 기존 타임라인·인라인 스타일을 revert. 리사이즈 후 옛 pin spacer가 남지 않게 한다.
- 데스크톱 두 pin이 연속돼도 사이에 자연스럽게 흐르는 제목/요약 여백이 느껴져야 한다. 사용자가 제자리에서 계속 휠을 돌린다고 느끼면 스크롤 길이를 줄인다.

## 7. 구현 구조와 안정성

- 새 독립 프로젝트라면 React + TypeScript + Vite + GSAP 정도의 작은 구성으로 시작. 기존 적합한 구현이 있으면 그 스택 유지. 라우터·상태 라이브러리는 실제 필요할 때만 추가.
- `SiteHeader`, `Hero`, `GroupbyObservation`, `BusinessModel`, `ExecutionEvidence`, `ProductWork`, `Recognition`, `AboutFooter` 정도로 의미에 따라 분리.
- 텍스트·링크·이미지 경로는 별도 content 데이터로 관리. theme은 CSS variables로 관리하고 A/B를 임의로 섞지 않는다.
- GSAP 플러그인은 한 번 등록. React에서는 useGSAP 또는 gsap.context 범위 안에서 생성하고 unmount에서 해당 범위만 revert. 전역 getAll().kill()로 다른 컴포넌트를 지우지 않는다.
- 애니메이션은 transform과 opacity 위주. width/height/top/left를 스크롤마다 갱신하지 않는다. React setState를 매 스크롤 프레임마다 호출하지 않는다.
- 폰트와 주요 이미지 decode 완료 뒤 필요한 시점에 ScrollTrigger.refresh. refresh를 onUpdate나 매 프레임에서 호출하지 않는다.
- 트리거는 문서 위→아래 순서로 생성. 필요한 경우 현재 공식 문서로 refreshPriority 방향을 확인; 스킬의 예제를 무검토 복사하지 않는다.
- 기본 CSS에서 콘텐츠 visible. JS가 없거나 GSAP이 실패해도 모든 카피와 링크에 접근할 수 있다. 초기 opacity:0 일괄 지정 금지.
- 이미지에는 width/height 또는 aspect-ratio. 아래쪽 이미지는 lazy, 히어로의 텍스트를 막는 대형 이미지 preload 금지.
- 폰트 display swap, 필요한 글꼴/굵기만 로드. 특히 명조 전체 CJK 폰트로 초기 로딩을 무겁게 하지 않는다.
- 이미지 원본 보존, 웹용 WebP/AVIF 등 파생본 생성. 문서 본문을 확대할 수 있을 만큼 선명하게 제공하되 원본 PNG 여러 장을 초기 일괄 다운로드하지 않는다.
- README, PDF, 사례 링크는 실제 배포 경로에서 작동하도록 만든다. 로컬 .md를 그대로 웹 상세페이지처럼 연결하지 않는다. 검증한 공개 GitHub/기존 사례 URL 또는 HTML 상세를 사용.
- 이메일·PDF·앱 링크에 가짜 버튼 없음. 새 창 링크에는 적절한 rel. 다운로드 파일명은 ASCII 별칭을 써도 화면 라벨은 한글 유지.
- 기본 메타 title/description, lang=ko, favicon은 절제된 문자 기반 가능. 추적 도구·연락 폼 백엔드·쿠키 배너를 임의로 추가하지 않는다.

4. 사용한 원본 자료 매핑 및 구현에 맞춘 카피 목록.
5. 빌드·링크·반응형·모션 감소 검수 결과와 남은 한계.

선택한 시안의 핵심은 보존하되, 실제 폰트 자형·문서 비율·가독성 때문에 달라진 부분은 설명한다. 공개 배포는 사용자 요청에 따라 진행한다.

## 11. 사용자 시안 검토 포인트

- 첫 화면의 큰 이름: A의 굵은 고딕 / B의 명조 중 어떤 인상이 본인에게 맞는가?
- 페이지 분위기: 밝은 종이 / 먹색과 백색 문서의 대비 중 어느 쪽인가?
- 그룹바이 제안의 비중과 72%의 크기가 적절한가?
- 히어로의 확정 문장 '사업을 기획하고, 필요한 제품을 만듭니다.'가 충분히 담백한가?

기술적 움직임은 정지 이미지로 검증할 수 없다. 최종 판단은 실제 스크롤 프로토타입에서 한다.
